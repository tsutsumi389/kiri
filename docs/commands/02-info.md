# kiri info

> [README](../../README.md) › [コマンド別ドキュメント](README.md) › kiri info

処理の前に画像の情報を得る。AIエージェントが座標を出す前に寸法を知り、`uniformity` で
その画像が処理可能か（単色背景か）を判断するために使う。

```
$ kiri info product.jpg
product.jpg
  寸法      1600 x 2000
  形式      jpeg
  EXIF回転  1
  色空間    sRGB
  透過      なし
  背景色    #F9F9F7  (均一度 1.00)
  外周ΔE    p50 0.4  p90 1.2  max 2.8
  外周勾配  p50 0.0  p90 1.0
  主体候補  0.2384,0.2308,0.7616,0.7692  (面積 25.8%, 信頼度 high)
```

```
$ kiri info product.jpg --json
{
  "width": 1600,
  "height": 2000,
  "format": "jpeg",
  "exif_orientation": 1,
  "orientation_applied": false,
  "color_space": "sRGB",
  "color_converted": false,
  "icc_profile": false,
  "has_alpha": false,
  "background": {
    "rgb": [249, 249, 247],
    "uniformity": 1.0,
    "perimeter_delta_e": { "p50": 0.4, "p90": 1.2, "max": 2.8 },
    "texture": { "p50": 0.0, "p90": 1.0 },
    "model": "flat",
    "field_range": [0.0, 0.0],
    "residual": { "p50": 0.4, "p90": 1.2, "max": 2.8 }
  },
  "subject": {
    "bbox": [381, 461, 1218, 1538],
    "normalized_bbox": [0.2384, 0.2308, 0.7616, 0.7692],
    "area_ratio": 0.2581,
    "capture_ratio": 0.9969,
    "delta_e": 55.68,
    "leftover_ratio": 0.0,
    "touches_edge": false,
    "level_rotation": 0.0,
    "level_fill_ratio": 0.9905,
    "border": 2,
    "confidence": "high"
  },
  "warnings": []
}
```

`uniformity` は外周サンプルのうち推定背景色から ΔE≤5 に収まる割合。0.9 を下回る画像は
単色背景ではないため、kiri の対象外として警告が出る。

`perimeter_delta_e` は外周が背景色からどれだけ離れているかの分布。`uniformity` が
低かったときに、その原因を切り分けるために使う。**`p50` が小さく `max` だけ大きければ
一部が外れているだけなので `--bbox` で切れば直る。`p50` から大きければ背景全体が
均一でなく、kiri の対象外である。**

`texture` は外周の帯で測った勾配（1px あたりの輝度変化量）の分布で、**背景が
ざらついていないか**を言う。色差では、なだらかな照明ムラと不織布の織り目が同じ値に
なってしまう。前者は `--tolerance` で吸収できるが、後者は輪郭の堤防を誤発火させる。
**`p50` が `--edge-threshold`（既定 8）に達していれば**、その背景は堤防を張れない
素材で、`cutout` はしきい値を `p90` の 1.5 倍へ自動で引き上げる。

判断に `p90` ではなく `p50` を使うのは、`p90` だけが高い状態が「背景がざらついて
いる」ではなく「**帯にざらついた物が写り込んでいる**」を意味するためである。商品が
画面の端で見切れていると外周の帯の 1 辺がまるごと商品になり、その商品が柄物なら
`p90` は跳ねるが `p50` は動かない。

`model` / `field_range` / `residual` は**背景を 1 色として持つか、照明場として
持つか**を言う（[背景は 1 色ではなく場で持つ](05-2-background.md#背景は-1-色ではなく場で持つ)）。
`info` が返す `model` は「この画像なら `cutout` がどちらを使うか」の予告である。

- `model` — 実際に効くモデル（`"flat"` / `"field"`）
- `field_range` — 場が大域の 1 色からどれだけ離れているかの `[最小, 最大]` ΔE。
  **場が何を吸ったか**を 1 行で言う。`"flat"` なら `[0, 0]`
- `residual` — 外周が**場**からどれだけ離れているかの分布。`perimeter_delta_e`
  （1 色に対する分布）とは別に持ち、両者の差がそのまま「場が吸った量」になる

**`uniformity` が低い理由は 2 つある。** 単色でないのか、単色に照明が乗っている
のか。前者は kiri の対象外だが、後者は照明場モデルが吸える。区別するのは
`residual` である。

| 素材 | `uniformity` | `perimeter_delta_e.p50` | `residual.p50` | 読み方 |
|---|---|---|---|---|
| 照明勾配のある紙（実写背景・合成 R7） | 0.33 | 6.7 | 1.0 | 照明が乗っているだけ。場で解ける |
| 不織布（実写 20MP のリモコン） | 0.20 | 11.9 | 4.9 | 照明 + 織り目。場は照明だけを吸う |
| 暗い机の上のキーボード（実写） | 0.16 | 21.6 | 1.9 | 場はよく吸うが、切り抜きは直らない |

**`residual` が小さいことは「解ける」の十分条件ではない。** 3 行目がそれで、
場は残差を 21.6 → 1.9 まで落とすのに、既定の切り抜きは前景比率 0.65 / 外周接触
ありのまま直らない。机の上には商品以外のもの（映り込み、別の物体、机の縁）が
写っており、**場が説明するのは「背景の照明」だけ**だからである。

**このとき `NOT_SEPARABLE` は出ない。** `separability` は効いたモデルに対する
色差なので、場が背景をよく説明するほど大きくなる（実測 24.6）。比べる相手も
同じモデルの `residual.p50`（1.9）なので、比は「分離できている」と言う——
そして実際、**背景の照明だけを見れば分離できている**。出るのは
`SUBJECT_TOUCHES_EDGE` / `CONTOUR_ROUGH` / `HALO_REMAINS` で、`info` は
`subject.confidence` を `low`（面積 0.4% / 捕捉率 50.8%）で返し、
「単色背景で撮り直すことを検討してください」と言う。**`info` と `cutout` の
どちらも「解けた」とは言わない。**

## `subject` — 商品はどこにあるか

`subject` は「背景色から遠い画素の、最大の連結成分」である。背景推定が既に持って
いる情報（背景色と外周の ΔE 分布）だけから求まるので、`info` の所要時間はほとんど
変わらない（20MP で 0.21s → 0.25s）。

**そのまま貼れる桁で出す。** テキストの「主体候補」行も `hint` も同じ丸め
（小数第 4 位）で、見栄えのために 2 桁へ落とさない。0.005 は 20MP で 28px にあたり、
bbox の外は色によらず背景と確定されるため、その差がそのまま商品の欠けになる。

`normalized_bbox` は **`--bbox <値> --normalized` にそのまま渡せる**。実写
（白い不織布の上の黒いリモコン、`uniformity` 0.20）では、ここが返す
`0,0.354,0.9834,0.662` を渡した結果が、人間が目で見て決めた
`0.02,0.33,0.98,0.64` と同じ品質（`foreground_ratio` 0.204 / `halo_ratio` 0.001 /
`separability` 54.7）になった。

## 傾きも同じ形で返す

`level_rotation` は**主体の最小外接矩形が軸に揃う回転角**（度、時計回りが正、
範囲は (-45, 45]）で、`cutout --rotate <値>` や `kiri rotate --angle <値>` へ
**そのまま渡せる**。傾きそのもの（符号を反転して渡す値）ではないので、符号を
考え直さなくてよい。

実写（白い不織布の上の黒いリモコン）では `-1.023` を返す。目視の印象より
ずっと小さい値で、実際にその角度で回すと `level_rotation` は `0.0` になる。

求め方は最小面積外接矩形である。主体の連結成分の凸包を取り、辺ごとに包を
回して軸並行の外接矩形の面積を測り、最小のものを採る。**どの角度でも面積が
変わらない形（円、辺の多い多角形）では `null` を返す**——`0` と報告すると
「傾いていないと測り切った」に読めるが、実際には測れていない。軸に揃った
矩形（正面から撮った箱）は測り切れているので `0.0` を返す。

**分解能は 0.1〜0.5 度**である。主体は縮小版で測るので、輪郭の量子化がそのまま
角度の誤差になる。小数第 4 位まで出るが、**0.5 度を下回る差を有意と読まないこと**
——「`level_rotation` が 0 になるまで回し直す」ループは組めない。

**自動では適用しない。** 傾きを直すかどうかは `bbox` と同じく構図の判断で、
kiri は測って返すところまでを受け持つ。

### その角度を信用してよいか（`level_fill_ratio`）

**最小面積外接矩形が「物の向き」を意味するのは、その物が実際に矩形に近いとき
だけである。** `level_fill_ratio` は**凸包の面積 / 最小面積外接矩形の面積**で、
1.0 に近いほどその矩形が形を実際に describe している。長方形は 1.0、角丸で 0.98、
取っ手つきの商品で 0.88 あたりまで落ち、**円は π/4≈0.785 が上限**である。

`level_rotation` が `null` のときは、ここも `null`。同じ凸包から同時に出る値なので、
片方だけが埋まることはない。

丸いものは `level_rotation` が `null` になるので止まる——と言いたいところだが、
**そうはならない。** どの角度でも面積が変わらないかを見る判定（相対差 2%）は
ラスタライズ後の量子化雑音を抜けてしまう。400x400 の画像に置いた円の半径を
60 から 170 まで 5px 刻みで振ると、`level_rotation` が値を返したのは 60 / 65 / 70
（いずれも **45.0 度**）と 85（0.0 度）の 4 つだった。

取っ手が 1 本生えるだけで、もっとはっきり抜ける。**水平に置いたフライパン**
（円＋取っ手、真値 0 度）に対して `level_rotation` は **-21.7 / +31.9 / -43.3 度**を
`confidence: "high"` で返す。最小の位置が取っ手と円の接し方——つまり輪郭の
量子化——で決まるためである。

| 形 | 真値 | `level_rotation` | `level_fill_ratio` |
|---|---|---|---|
| 長方形（t=0〜30 度） | 同左 | 一致 | 0.993-1.000 |
| 角丸 360x220（t=0〜30 度） | 同左 | 一致 | 0.973-0.980 |
| 手提げ袋 | 同左 | 一致 | 0.997-1.000 |
| 実写（不織布の上のリモコン 4 枚） | — | — | 0.903-0.968 |
| マグ（取っ手つき） | 同左 | 一致 | 0.881-0.899 |
| 円 d=240 / 320 | 測れない | 45.0 / 0.0（誤） | 0.795-0.797 |
| 楕円 360x200 | 同左 | +1.3/+1.6 ずれ | 0.780-0.788 |
| L 字 / 三角 | 同左 | 三角 t=12 は 42.0（誤） | 0.512-0.788 |
| フライパン（円＋取っ手） | 同左 | -21.7/+31.9/-43.3（誤） | 0.674-0.676 |

**持ち手の下が空いていても値は下がらない。** 凸包は凹みを埋めるので、手提げ袋は
1.0 に張り付く。ここで測っているのは「凹みの深さ」ではなく「`level_rotation` を
決めたその包が、最小外接矩形をどれだけ埋めるか」である。

**`level_rotation` を読んで `kiri rotate --angle` へ渡す経路でも、同じ値で同じ
判断をすること。** `cutout --rotate auto` は 0.85 を門にしている
（[傾きを測って直す](05-5-finishing.md#傾きを測って直す--rotate-auto)）。

## 判定は `--border` に依らない

`subject.border` は**主体の統計を測った外周の帯**である。既定では `--border` と
同じ値だが、`--border` が短辺の 3% を超えるとここで頭打ちになる。

`--border` は背景色の推定範囲を決める値であって、主体の較正のための値ではない。
だが帯が変われば外周 ΔE の分布——「背景と違う」と判じるしきい値そのもの——も
変わるので、放っておくと較正が `--border` にぶら下がる。上限を置く前は、
`--border 110` で救えない画像（暗い机の上のキーボード）が `"high"` と名乗って
いた。いまは帯を 2 から 400 まで振っても較正 11 点の判定は 1 つも動かない。

**`confidence` が `"high"` のときだけ、この矩形と角度を根拠に動いてよい。**
判定は 3 つの数値の AND で行う。

| | 意味 | High の条件 |
|---|---|---|
| `area_ratio` | 最大成分が画像に占める割合 | 0.05 以上 |
| `capture_ratio` | 閾値を超えた画素のうち最大成分が占める割合 | 0.70 以上 |
| `leftover_ratio` | **この矩形の外**に残った、背景と言えない画素の最大の塊 | 0.15 未満 |

**`"high"` は矩形についての言明である。角度についてはもう 1 つ要る。** 最小面積
外接矩形が向きを語るのは形が矩形に近いときだけなので、`level_rotation` を使う前に
`level_fill_ratio` を見ること（[その角度を信用してよいか](#その角度を信用してよいかlevel_fill_ratio)）。
水平に置いたフライパンは、3 つの数値をすべて満たしたまま `-21.7` 度を名乗る。

はじめの 2 つは「見つけたものが商品らしいか」を言う。面積だけでは足りない
（**背景が広くざらついていれば、大きな塊はいくらでもできる**）ので、
`capture_ratio` が「背景と違う画素が 1 箇所にまとまっているか」を添える。
実写 2 枚が両側から挟んで較正した。

| 素材 | area_ratio | capture_ratio | 判定 |
|---|---|---|---|
| 不織布の上のリモコン | 0.234 | 0.979 | high（bbox で救える） |
| 暗い机の上のキーボード | 0.004 | 0.508 | low（救えない） |

### 3 つ目は「見落としていないか」を言う

主体を「背景から遠い画素」として拾う以上、遠さの基準は外周 ΔE の `p90` である。
商品が画面の端で大きく見切れて外周サンプルの 1 割以上を占めると、**その商品自身が
基準を吊り上げ、自分で作った基準を越えられなくなる。** このとき残るのは輪郭に
生じたわずかな滲みだけで、`capture_ratio` は 1.0 近くに張り付く——**誤検出を弾く
はずの捕捉率が、この構図では誤検出を後押しする向きに反転する。**

**これを外周の統計から当てにいく道は行き止まりだった。** 外周 ΔE が二峰性
（`p50` が小さいのに `p90` が大きい）なら汚染、という規則を一度入れて、両側から
破れた。

- `p50 < 5` は「背景にノイズが一切無い」ことを要求する。布・紙・JPEG のノイズが
  あるだけで超えるので、**実写ではほぼ発火しない**（リモコンの `p50` は 11.9）。
  kiri 自身のテストが持つ織り目テクスチャの上に同じ汚染構図を置くと `p50` が
  6.30 まで上がり、判定は素通しして誤った矩形を勧めた
- 逆に、下端に影の帯があるだけの画像（`p50` 0.00 / `p90` 17.7）は主体を完璧に
  捉えている（`area_ratio` 0.141 / `capture_ratio` 0.981）のに `low` へ落ちた

**外周だけを見ている限り、「背景がざらついている」と「主体が外周に乗っている」は
同じ値になる。** これは ΔE と勾配が単体では
突き当たったのと同型の限界（「背景がざらついている素材」の節を参照）であり、
係数をいじって越えられるものではない。

**そこで、外周を疑うのをやめて、出した答えを検証することにした。**

> 提案した bbox の外に、背景とは言えない大きな塊が残っていたら、その答えは
> 主体を取りこぼしている。信用してはならない。

検証のしきい値は `max(p50, 5.0)` で、**主体検出に使う `max(p90, 5.0)` より低い。**
高いほうは主体自身に汚染されている可能性があり、**汚染を検出するのに汚染された
物差しを使うことになる**（取りこぼした物体ほど「背景」と数えられて
`leftover_ratio` が 0 に落ちる）。

較正は 13 シーンで行う。**合成の 11 枚は `tests/common` の `subject_scenes()` が
作り、`cargo test --release --test cli -- --ignored print_the_subject_calibration`
で表ごと取り直せる。** 残り 2 枚は実写である。

**この表は Phase 4 で取り直した。** 数値が前版から動いているのは判定が変わった
からではなく、**シーンそのものが入れ替わった**ためである（「縦に抜ける帯状の
商品」→「画面の 4 割を占める物体だけ」、「白地に白い商品」→「白地に淡色の商品」
など）。`high` / `low` の判定はどの行も裏返っていない。

| シーン | area | capture | leftover | 判定 |
|---|---|---|---|---|
| 画面外へ抜ける大きな物体 | 0.097 | 0.961 | **35.2%** | low |
| 同じ構図を織り目の上に置いたもの | 0.097 | 0.961 | **35.0%** | low |
| 画面の 4 割を占める物体だけ | 0.004 | 1.000 | **39.2%** | low |
| 下端に影の帯 | 0.147 | 0.974 | 4.0% | high |
| 下端に境界すれすれの帯 | 0.147 | 0.974 | 4.0% | high |
| 左辺に小道具が写り込む | 0.147 | 0.907 | 1.5% | high |
| なだらかな勾配の背景 | 0.149 | 0.933 | 3.7% | high |
| きれいなスタジオ背景 | 0.147 | 1.000 | 0.0% | high |
| 白地に淡色の商品 | 0.141 | 1.000 | 0.0% | high |
| 広い落ち影 | 0.208 | 1.000 | 0.0% | high |
| 商品が 2 つ | 0.091 | **0.500** | 9.1% | low |
| 不織布の上のリモコン（実写） | 0.234 | 0.979 | **4.1%** | high |
| 暗い机の上のキーボード（実写） | 0.004 | **0.508** | 23.8% | low |

**0.15 の根拠**は、`high` が正解のものの最大が 4.1%（実写のリモコン）、この規則で
落とすべきものの最小が 23.8%（実写のキーボード）であること。下へ 3.7 倍、上へ
1.6 倍の余裕がある。上下が非対称なのは意図的で、誤って `high` にする
（存在しない矩形を勧める）ほうが、誤って `low` にする（助言を出し損ねる）より
害が大きいためである。

「商品が 2 つ」の 9.1% が 0.15 を下回るのは目を引くが、この行は
`capture_ratio` 0.500 で既に `low` になっており、`leftover_ratio` が単独で
支えている行ではない。2 つ目の商品まで leftover で弾こうとすると閾値を 0.09
付近まで下げることになり、影や小道具の側（実写 4.1%）との余裕が消える。

**`subject` は背景を 1 色として測る。** 照明場モデル（`--background-model field`）
を入れても、この 13 行の判定は 1 件も動かない。場に対して測る案は試したが、
**商品が外周の帯を大きく占める画像で 2 件が裏返った**——場は帯から作るので、
そこで商品の色を「背景」として学んでしまい、取りこぼした物体が `leftover_ratio`
に残らなくなる。

| シーン | 1 色 | 場に対して測った場合 | 正しい判定 |
|---|---|---|---|
| 画面の 4 割を占める物体だけ | low | **high** | low |
| 暗い机の上のキーボード（実写） | low | **high** | low |

**この較正は既定の `--border 2` を前提にしている。** `--border` は背景色の推定
範囲であると同時に外周 ΔE の分布——つまり上の 2 つのしきい値の材料そのもの——を
決めるため、大きく広げると成立しない。実測ではキーボードが `--border 110` で
`high` に裏返り、誤った矩形を勧め始める。既定から大きく動かしたときは
`confidence` を根拠に動かないこと。

**`--bbox` を指定して `cutout` を回したときも、`subject` は画像全体から測り直した
矩形であり「適用した bbox」ではない。** 指定が効いたかどうかは `mask.bbox` と
`settings` を見ること。

**`delta_e` は判定に使っていない。** キーボードの誤検出領域は背景との色差が
ΔE 64 とリモコン（ΔE 50）より大きく出る。色の違いの大きさは「そこが商品か」を
何も語らない。`delta_e` を返すのは別の用途——それが外周の `p50` を下回るなら、
背景を消せる `--tolerance` では商品も消えるので、パラメータ調整では救えない——
のためである。

検出できなければ `null`。キー自体は常に出す（`separability` / `halo_ratio` と
同じ規約）。

### なぜ kiri はこの bbox を自動で適用しないのか

**bbox は構図の意思決定だからである。** 商品が 2 つ写っていればどちらを残すのか、
意図的に見切れさせた構図をそのまま出すのか——kiri には決められない。矩形を黙って
適用すると、その判断を利用者から取り上げたうえ、結果の JSON からは何が起きたのか
分からなくなる。

`edge_threshold` の自動調整（背景のテクスチャに応じた引き上げ）とは性質が違う。
あちらは純粋な内部パラメータで、正解が画像から一意に決まり、値は `settings` に
出るので後から検算できる。bbox にはその意味での正解が無い。

| オプション | 既定値 | 説明 |
|---|---|---|
| `--border` | 2 | 背景色推定に使う外周の幅(px)。**`subject` の信頼度判定にも効く**（上記の較正は既定値が前提） |
| `--segment` | off | `subject` をセグメンテーションモデルから測る。`off` / `auto` / `isnet`。**既定のビルドには入っていない**（[意味の事前知識](05-4-guidance.md#意味の事前知識モデルに何を聞くか)） |
| `--model-path PATH` | — | モデルの ONNX を直接指す。未指定なら `$KIRI_MODEL_DIR` > `$XDG_CACHE_HOME/kiri/models` > OS 既定のキャッシュ。**大きさやダイジェストが違うファイルも読む**（`MODEL_SIZE_UNEXPECTED` / `MODEL_DIGEST_UNEXPECTED`） |
| `--no-color-convert` | | 埋め込み ICC を解釈せず、画素の値をそのまま使う |
