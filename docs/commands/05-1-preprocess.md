`kiri cutout` の説明は 7 つのファイルに分かれている。全体の索引は [kiri cutout](05-cutout.md#読む順) にある。

## 背景をグレーカードとして色を正す（`--white-balance` / `--exposure`）

EC の素材は「白い紙・布の上に商品を置いて撮る」形がほとんどである。つまり**画面の
大半に、本当は無彩色で、本当は明るいはずの面が写っている。** それをグレーカードと
して読めば、オートホワイトバランスが外した色かぶりと、露出が外した明るさを、
線形 RGB の対角ゲイン 1 回で正せる。

```
$ kiri cutout remote.jpg -o out.png --white-balance auto --json
```

```json
"color": {
  "white_balance": "auto", "exposure": "off",
  "status": "applied", "source": "field",
  "white_point": [178, 173, 164], "white_point_shift": 4.8,
  "gain": [0.9433, 1.0071, 1.1203],
  "exposure_stops": 0.0, "clipped_ratio": 0.015
}
```

**どちらも既定 off で、渡さない実行では出力画像も結果 JSON も 1 バイト変わらない。**
`--shadow` / `--segment` と同じ規約である。

### 既定 off の理由

**1 枚の画像からは「色のある背景」と「色かぶりした中性背景」を区別できない。**
青い背景紙の上の商品と、青くかぶった白背景の商品は、画素としては同じものである。
前者に白点を当てれば背景は灰色になり、商品の色は青の補色へ転ぶ。中性度の門はその
事故を狭めるだけで、無くせない。

加えて**切り抜きの指標が良くなる保証が無い。** 実写 2 枚では `halo_ratio` と
`contour_roughness` が下がる一方で `separability` も下がる（悪化する）。
得るものが「見た目の色が揃う」に限られる段なので、利用者が求めたときだけ動かす。

### 切り抜きより前に掛かる

色かぶりと露出のずれは、切り抜きの**判定そのもの**を狂わせる。背景と商品の ΔE、
外周のばらつき、`separability`——どれも色の上で測る値なので、正す前の数値と正した後の
数値は別物である。そこで読み込みの直後に置き、**以降のすべて（モデルの推論・背景の
見立て・`subject`・`--optimize` の探索・切り抜き・診断）は正された画素で測り直される。**

推定に使う背景の見立てだけは正規化前の画像から 1 度だけ測る。`--bbox` や空間的な指示は
その前に解けているので、それを材料に入れた照明場が使われる。

### 何をどう推定するか

白点 W は、照明場が立っていればその**格子セルの線形 RGB のチャンネルごとの中央値**、
1 色モデルならその 1 色である。どちらから測ったかは `color.source` が `field` / `flat` で
返す。ゲインは**輝度を変えない** von Kries（`g_c = Y / W_c`）なので、白点を当てても
絵の明るさは動かない。

露出は背景の輝度を固定の狙い（L\* 96 ≒ sRGB 243）へ運ぶスカラー `k` で、
`color.exposure_stops` が `log2(k)` を返す。**負にもなる**——背景が狙いより明るければ
下げるほうが正規化である。

### 当てない条件（段ごとに落ちる）

| 段 | `data.reason` | 断る理由 |
|---|---|---|
| 白点 | `not_neutral` | 背景の彩度（`white_point_shift`）が上限を超えた。色紙を中性化しない |
| 露出 | `not_light` | 背景の明度が下限を下回った。暗いグレーを白まで持ち上げるのは正規化ではない |
| 両方 | `gain_out_of_range` | 合成ゲインが 2 段を越えた。背景の見立てが外れている疑いが強い |
| 両方 | `would_clip` | 当てると新たに白へ飽和する（線形の 1.0 を超える）画素が予算（3%）を超える |
| 両方 | `no_material` | 背景を 1 画素も測れなかった |

**白点だけが落ちる／露出だけが落ちる／両方落ちる**の 4 通りがすべて起こる。落ちた段は
`WHITE_BALANCE_SKIPPED` / `EXPOSURE_SKIPPED` が数つきで言い、両方落ちれば警告は 2 本
出る。

合成ゲインで初めて門を越えたときは、**実際に門を押し出している段**を諦める。白飛びなら
持ち上げている側で、露出が暗くする側（`exposure_stops` が負）なら落ちるのは白点のほうに
なる——輝度を変える対角ゲインではないとはいえ、**白点は必ず弱いチャンネルを持ち上げる**
ので、飽和を作るのは白点でありうる。範囲なら越えている向きへ押している側を落とす。

**警告の並びは契約ではない。** 諦めた順に並ぶが、どちらが先かは素材が決める。
受け手は並びではなく `code` で分岐する。

`color.status` は `applied` / `no_change` / `skipped` の 3 値で、**`no_change` と
`skipped` は別である。** 前者は背景がすでに中性で狙いの明るさだった（直すものが無い、
警告も出ない）、後者は門が閉じた。**片方の段だけが落ちた実行は `applied`** で、
絵は変わっている。

### batch の spec

```json
{
  "defaults": { "white_balance": "auto" },
  "items": [
    { "input": "a.jpg", "output": "out/a.png" },
    { "input": "b.jpg", "output": "out/b.png", "white_balance": "off" }
  ]
}
```

綴りと値は CLI と同じで、読めない値はその項目を `SPEC_INVALID` で落とす。
`defaults` からの継承も他の設定と同じ規約である。

### 限界

- 背景が本当に色紙なら `off` のままにする（既定がそれである）
- 商品が画面の大半を占める素材では白点が商品の色を吸う。`--bbox` で商品を囲えば
  場の材料から外れる（警告の `hint` がそれを言う）
- 白点は対角ゲイン 1 回で、混色行列（色順応変換）は使わない。対角で足りない素材は
  そもそも「背景が無彩色である」という前提が成り立っていない
- 露出は背景を狙いに乗せるだけで、商品の明るさは見ていない。トーンカーブを当てる段
  ではない
- `--no-color-convert` と併せると、門は入力の色空間のまま C\* と L\* を測る。Display P3 を
  素通しした実行では判定が sRGB のときと変わる（既存の ΔE 経路と同じ前提だが、
  **この段は画素そのものを書き換える唯一の段**である）
- `color.source` と `background.model` は食い違うことがある。前者は正規化**前**、
  後者は正規化**後**の画素から測った見立てである

## 背景がざらついている素材（不織布・段ボール・畳）

この堤防には裏がある。**背景の素材そのものが 1px あたり十数の変化を持っていると、
堤防は背景の中で壁になる。** 不織布の上に置いた黒いリモコンの実写では、外周の帯の
26% が堤防の画素になり、フィルは外周から数 px も進めなかった（前景比率 0.94、
つまり「ほとんど何も消えない」）。

そこで、外周から短辺の 3% の帯で勾配の分布を測り（`background.texture`）、
**`--edge-threshold` が未指定で、かつ帯の `p50` が既定の 8 に達しているときに
限り、しきい値を `p90` の 1.5 倍まで自動で引き上げる**。

| 背景 | p50 | p90 | 効いた堤防 | 前景比率 |
|---|---|---|---|---|
| スタジオ背景 | 0.0 | 1.0 | 8（既定のまま） | 変化なし |
| 下端で見切れた柄物の商品 | 0.4 | 19.2 | 8（既定のまま） | 変化なし |
| 不織布（実写 20MP） | 11.3 | 27.9 | 41.8 | 0.94 → 0.204 |

**発火の判断に `p50` を使うのが要点である。** `p90` だけが高い状態は「背景が
ざらついている」ではなく「帯にざらついた物が写り込んでいる」を意味する。EC で
頻出する「商品が画面の下端で見切れている」構図では帯の 1 辺がまるごと商品になり、
その商品が柄物なら `p90` は跳ねる。`p90` で判断すると背景はきれいなのに堤防が
上がり、堤防が守るはずだった淡色商品が背景ごと消える。

無効化ではなく引き上げにしてあるので、織り目の上に載った淡い商品も、輪郭の勾配が
織り目より大きい限り守られる。

**黙って値を変えることはしない。** 効いた値は `settings.edge_threshold` に、
変えた理由と根拠の数値は `warnings` に 1 行出る。`--edge-threshold` を明示すれば
その値に従う（`0` を指定すれば従来どおり無効化される）。

```
警告: 背景のテクスチャ（外周の勾配 p50 = 11.3 / p90 = 27.9）が堤防を
      発火させるため、edge_threshold を 8 から 41.8 へ調整しました。
      明示指定すれば従います
```
