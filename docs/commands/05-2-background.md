# cutout: 背景の推定とフィル

> [README](../../README.md) › [コマンド別ドキュメント](README.md) › [kiri cutout](05-cutout.md) › 背景の推定とフィル

`kiri cutout` の説明は 7 つのファイルに分かれている。全体の索引は [kiri cutout](05-cutout.md#読む順) にある。

## 背景は 1 色ではなく場で持つ

kiri の背景モデルは長いあいだ「外周の中央値 1 色」だった。実写ではこれが破れる。

**紙や布に照明が斜めに当たれば、外周の帯は 1 色では表せない。** 不織布の上の
黒いリモコン（実写 20MP）は外周 ΔE が p50 11.9 / max 60 で、**ガウスぼかし r=4 で
織り目を消しても**（1px あたりの勾配 p50 11.3 → 3.9）外周 ΔE の p50 は 11 のまま
残った。残っているのは織り目ではなく、**照明ムラとしわの大域変動**である。

その変動を 1 色 + `--tolerance` で飲むには tolerance 60 が要った。60 は淡色商品を
まるごと飲む値で、実際 tolerance 70 では商品が削れた（前景比率 0.078）。
**「背景を消せる値」と「商品を残せる値」が両立しない**のは、背景が 1 色だと
思い込んでいるからで、素材のせいではない。

そこで背景を位置の関数 B(x, y) として推定する。色差を**その場の背景色との差**で
測れば、低周波の照明変動は場が吸い、`--tolerance` は織り目や圧縮ノイズの振幅
（ΔE 10 前後）だけを受け持てばよくなる。

### 場の作り方

1. 長辺が 256 になる格子（20MP で 256×192）に切り、セルごとに「**既知の背景**」
   画素の**中央値**を採る。既知とみなすのは 4 つ——外周の帯（短辺の 3%）、
   `--bbox` の外側、確定背景（`--trimap` など）、そして信頼度 `high` の
   `subject` の矩形を 5% 広げた外側。平均ではなく中央値にするのは、商品の縁が
   掛かったセルで平均が引きずられるためである
1. **どの源から来た画素にも色の門を掛ける**（下の節）。1 色の中央値から
   `max(15, 2 × perimeter_delta_e.p50)` より遠い画素は材料にしない。
   門を通った帯の画素が 30% を切ったら場そのものを諦め、1 色へ落ちて
   `BACKGROUND_FIELD_SKIPPED` を出す
2. 標本がセルの面積の 1/4 に満たないセルは「未知」とし、**正規化畳み込み**
   （既知の値と重みを同じ核でぼかし、値 ÷ 重み）で埋める。埋めた値は次の回の
   材料に戻し、全セルが埋まったあともさらに数回回して緩める
3. 既知のセルは毎回もとの中央値に打ち直す。最後に σ = 1 セルで全体を均す
4. **1 回目のフィルが終わったら、その結果（背景と判定した画素すべて）を材料に
   場を作り直し、もう一度フィルする**。外周の帯と矩形だけでは、商品が中央を
   大きく占める画像で場の内側がほとんど外挿になる

推定は決定的で、乱択を使わない。**全解像度の表は作らない**——12MP の Lab の表は
72MB あり、フィルが持つ画素ごとの Lab と二重に積む余裕が無い。場は格子 +
双線形補間で都度引く。20MP での実測は **27.2 ms / 約 2MB**（設計の予算は
30ms / 5MB）。`cutout` 全体では 2 回目のパスを含めて **+312 ms**（20MP で
3021 ms → 3332 ms）かかる。

### 場の材料に掛ける色の門

**場は「物体を表せてしまう」。** 材料の第一は外周の帯なので、商品が画面の端で
見切れていれば帯の 1 辺がまるごと商品の内部になり、場はそこで**商品の色を背景
として学ぶ**。学んだ場の上では商品は背景と一致し、見切れた部分がまるごと消える。
消えた結果 `SUBJECT_TOUCHES_EDGE` も出なくなるので、**エージェントからは成功に
見える**——いちばん筋の悪い壊れ方である。

| シーン | 正しい前景比率 | 門なしの既定 |
|---|---|---|
| 白背景・下端で見切れ（商品が外周の 17.5%） | 0.3150 | **0.1713** |
| 同上・見切れが浅い版 | 0.1750 | **0.1000** |
| 画面外へ抜ける大きな物体（合成） | 0.4461 | **0.1226** |
| 画面の 4 割を占める物体だけ（合成） | 0.4000 | **0.0202** |
| 4 辺へ抜ける大きな商品（合成） | 0.8445 | **0.2917** |
| 照明勾配 + 下端で見切れ | 0.3150 | **0.1673** |

**外周の統計量で `auto` の切り替えを止めても解けない。** 「照明勾配 + 見切れ」
（`uniformity` 0.38 / 外周 ΔE p50 6.7）と R7（0.34 / 6.7）は区別がつかない。
効くのは**場の材料そのものに門を掛ける**ことだけで、1 色の中央値から遠い画素は
どの源から来ていても材料にしない。物体は 1 色の中央値から遠く、照明ムラは近い、
という差だけを使う。

```
門 = max(15, 2 × background.perimeter_delta_e.p50)   （ΔE）
```

倍率が「2」なのは、実素材の帯では p90 が p50 の 2.2〜2.5 倍に来るからである
（実写リモコン 26.75 / 11.93、R7 16.7 / 6.73）。つまりこの門は「**背景が自分で
見せているばらつきまでは材料に入れ、その外は物体とみなす**」と言っている。
下限の 15 が要るのは、白背景に見切れた商品という構図では p50 が 0.0 になり、
倍率だけでは門が閉じきってしまうためである。

両側から挟んである。

| 門 | 実写リモコン（bbox なし `--tolerance 20`） | 織り目の上の大きな物体（合成） |
|---|---|---|
| 20 以下 | **外周接触が残る**（前景比率 0.221） | 物体は残る |
| 既定（リモコン 23.9 / 汚染シーン 15） | 外周接触なし・前景比率 0.219 | 物体は残る（0.4461） |
| 18 以上（汚染シーン側） | 外周接触なし | **物体が消える**（0.1068） |

**分けられない組が 1 つある。** 合成の「下端に境界すれすれの帯」（背景に落ちた
影、ΔE 17.67）と「織り目の上の大きな物体」（ΔE 17.74）は **0.07 しか違わない**。
門を 18 まで広げれば影は場に吸われるが、同時に画面の 35% を占める物体が背景として
学ばれる。**色差だけでは「背景に落ちた影」と「背景に置かれた物体」を分けられない**
ので、kiri は**物体を消さない側へ倒してある**——影が前景に残るのは `--bbox` 一つで
解けるが、消えた商品には誰も気づかない。

### 場が吸うもの、残すもの

| 乗っているもの | 1 色モデル | 照明場モデル |
|---|---|---|
| 照明の勾配・ビネット・しわ（低周波） | `--tolerance` を広げるしかない | **場が吸う** |
| 織り目・繊維（高周波） | 堤防が誤発火する | 残る（堤防の自動調整が受け持つ） |
| JPEG のブロックノイズ | `--tolerance` が受け持つ | 同左 |
| 2 色に割れた背景の**段差** | 片方が残る | 段差は表せない。段の両側が外周に見えていれば追える |

### 何が変わったか

`--background-model auto`（既定）は `uniformity` が 0.90 を下回るときだけ場を使う。
**均一な背景では出力が 1 バイトも変わらない**（回帰の基準を動かさないため）。

| 素材 | 設定 | 1 色 | 照明場 |
|---|---|---|---|
| 照明勾配のある紙 + 黒商品（合成 R7） | 既定 | 前景比率 0.463 / 輪郭誤差 59.1 / 縁の汚染 0.570 | **0.375 / 0.41 / 0.000**（正解 0.375） |
| 照明勾配の背景（合成 S13） | 既定 | 0.410 / 9.77 / `HALO_REMAINS` | **0.375 / 0.46 / 警告なし** |
| 不織布の上のリモコン（実写 20MP） | bbox なし `--tolerance 20` | 外周接触あり | **外周接触なし / 前景比率 0.219** |
| 不織布の上のリモコン（実写 20MP） | bbox あり `--tolerance 12` | 外周接触あり / 前景比率 0.278 | **外周接触なし / 0.227** |
| 照明勾配の不織布 + 黒商品（合成 R2） | 既定 | 0.502 / 121.5 / 0.854 | 0.390 / 109.4 / 0.608（**まだ切れない**） |

実写のリモコンは、**1 色モデルでは bbox + `--tolerance 60` が要ったところを、
場があれば bbox 無しの `--tolerance 20` で切れる**。1 色に戻したければ
`--background-model flat` を渡す。

**不織布（R1 / R2 / R5 / R6）は場を入れても切れない。** 残っているのは照明では
なく織り目で、これは堤防（`EDGE_THRESHOLD_RAISED`）の担当である。場は近づける
（R2 の縁の汚染 0.854 → 0.608）が、外周接触は解消しない。

**`--bbox` を足した `assisted` でも tolerance は下げられなかった。** 設計では
「場が変動を吸うぶん tolerance 60 は要らなくなる」と見込んでいたが、掃引の実測
（`print_the_assisted_tolerance_sweep`）では R1 / R2 / R5 / R6 とも 60 が最良の
ままで、下げるほど輪郭誤差も縁の汚染も単調に悪化した（R1: 60 で 4.23 / 0.176 →
12 で 19.48 / 0.579）。場が吸うのは低周波の照明変動であって、織り目そのもの
（1px あたり十数の振幅）ではない。

**黙って切り替えることはしない。** 効いたモデルは `settings.background_model` に、
場の振れ幅と残差は `warnings` に 1 行出る。`EDGE_THRESHOLD_RAISED` と同じく
**直すものがあるという意味ではない**ので、この警告に `hint` は付かない。

```
警告: 背景が均一でないため、背景を 1 色ではなく照明場として推定しました
      （場の振れ幅 ΔE 0.2〜20.9、場に対する外周残差 p50 = 1.0 / p90 = 2.6）
```

**場を作れなかったときも黙らない。** 商品が画面をほぼ埋めて外周の帯の大半が
商品になると、門を通った材料からは当てずっぽうの場しか作れない。そのときは
1 色へ落ち、`settings.background_model` は `"flat"` と出る——`--background-model
field` を明示していてもである（**効いた値だけを報告する**）。理由はこの 1 行に
しか書いていない。

```
警告: 外周の帯のうち背景として使えたのが 15% しかないため、照明場を諦めて
      背景を 1 色で測りました
```

## フィルは 3 段に分かれている

連結性と勾配の堤防だけでは淡い色の商品を守れない。堤防は「1px あたりの輝度変化が
しきい値(8)を超える画素には入らない」という規則なので、**局所的にコントラストが
足りない場所が 1 箇所でもあればそこから内部へ流れ込む**。商品の内部は一様なので、
入られたら許容量いっぱいまで削られる。逆に落ち影の濃い部分は ΔE 20-30 あり、
`--tolerance 12` では届かない。この 2 つは 1 つのしきい値の裏表で、色の許容量を
どう動かしても両立しない。

そこでフィルを 3 段に分ける。

1. **芯** — 背景と言い切れる厳しい許容量で、外周から届く範囲だけを塗る。この許容量は
   外周 ΔE の分布から自動で決まる（利用者に見せる値ではない）。「どこまでを背景と
   言い切れるか」は画像ごとに違い、その答えは外周の分布が持っているためである
2. **拡張** — 芯から `--tolerance` の範囲へ広げる。ただし **1px あたりの色差が
   `--step-tolerance` 以下の滑らかな経路でしか進めない**。芯に入れる色の画素は
   この検査を免除するので、圧縮ノイズの多い背景に穴は残らない
3. **影** — Lab で彩度差が小さく明度だけ低い画素を、`--shadow-tolerance` の範囲で
   さらに吸収する（次節）

段差の検査では「その先が平らかどうか」も見る。落ち影の裾は最も急なところで 1px あたり
ΔE 1.9 変化し、淡色商品の輪郭はアンチエイリアスで 2px に広がると 1px あたり ΔE 1.8
になる。**数値が同じ以上、片方だけを止めるしきい値は存在しない。** 分けられるのは
「その先も変化し続けるか、1-2px で一様な面に入るか」だけである。

加えて、フィル後の背景を `--seal` px 収縮して外周に連結する成分だけ残し、同じだけ
膨張させる（測地的オープニング）。**幅 2N px 以下の隙間を通ってしか外周につながらない
領域は前景へ戻る**ので、輪郭に 1-2px の破れができても浸水しない。取っ手の内側のような
正当な隙間は、既定の 1 では塞がらない（幅 3px から抜ける）。

封鎖幅は `--seal` だけで決まり、`--edge-threshold` には左右されない。堤防は隙間の
両側を背景候補から外すので、素直に組み合わせると通路が 2px 細って見え、3px の隙間まで
塞いでしまう。収縮に掛ける前に「背景色なのに堤防で外された画素」を戻すことで、
2 つの仕組みが互いの効き目を変えないようにしてある。

## 落ち影の扱い

**落ち影は背景として消す。** EC 用途では商品単体の切り抜きが求められることが多く、
複数商品の見た目も揃うため。影を残したい場合は `--shadow-tolerance 0` を指定する。

影と判定するのは、Lab で **背景との彩度差が小さく（a\*b\* 平面で 4 以下）、明度だけが
低い**（0 < L\*の落ち込み ≤ `--shadow-tolerance`）画素である。無彩色の面に落ちた影は
光量だけが減るので彩度がほとんど動かない、という物理から来ている。茶色い革や紺の布は
彩度が動くので影とは取り違えない。

中間グレーや黒の商品も「背景より暗い無彩色」なので、この条件だけなら影候補になる。
それでも消えないのは、**輪郭の段差でフィルが止まる**からである。影の吸収は第 2 段の
背景から一定の距離（画像の短辺の 1/24、最低 16px・最大 64px）までに制限してあり、
輪郭のどこかに通り道ができても被害はその範囲に留まる。上限があるのは、比例だけだと
3000px 級の素材で 125px まで伸び、柔らかい輪郭を通り抜けた判定が商品の内部へ
届いてしまうためである。

**背景より明るい映り込みは対象外。** グレー背景での光沢や反射は明度が上がる方向に出るが、
それを影と同じ規則で飲み込むと白背景の白い商品のハイライトまで消えてしまう。
明るい映り込みを消したい場合は `--bbox` で範囲を切る。

消した影の代わりが要るときは、切り抜いたアルファから影を作り直せる
（「[落ち影を合成する](05-5-finishing.md#落ち影を合成する)」）。
