## 境界は matting として解く（形ではなく色から決める）

フィルが返すのは 0/255 の二値マスクでしかない。ここに階調を与える方法として、
マスクをぼかす（フェザリング）のは筋が悪い。**それはマスクの形から作ったアルファであって、
画像に写っている本当のエッジ位置とは無関係だから**である。実際、
[フィルを止めるエッジ堤防](05-cutout.md#仕組み)は
勾配が立つ画素を前景側に残すので、輪郭の外に **色が完全に背景のままの 1px の縁**が残る。
これを半透明にしても、背景色を取り除く復元式は背景色をそのまま返す。白い下地では
気づかないが、黒や色付きの下地に載せた瞬間に輪郭が光る。

そこで境界に帯を張り、帯の各画素で**近傍の確定前景色 F と確定背景色 B を集めて、
観測色 C を F–B 直線へ射影する**。撮影された境界画素は C = aF + (1-a)B の混色なので、
これを a について解けばよい。計算は線形 RGB で行う。合成は光の量の足し算であり、
ガンマの掛かった sRGB 値のままでは混色が直線に乗らないためである。同じ F・B から
商品色も復元するので、デスピルは別処理ではなく同じ推定の裏返しになる。

帯の幅は輪郭ごとに測る。境界から外へ進んで色が背景に収束するまでの距離と、内へ進んで
商品色に収束するまでの距離の大きいほうを採る。**くっきりした輪郭に広い帯を張れば商品の
内側まで巻き込み、8px かけて溶ける輪郭に狭い帯では遷移を跨げない。**

### それでも足りなかった — 輪郭そのものが背景のテクスチャで決まっている

射影は「二値マスクの輪郭が正しい場所にある」ことを前提にしている。実写背景では
その前提が崩れる。フィルは画素ごとに「候補か否か」で止まるので、織り目の粒 1 つ
1 つで停止位置が前後し、不織布の暗い孔や繊維の影は黒い商品との混色（アルファ
0.3〜0.6）と画素単位では区別がつかない。**正解を持った合成ベンチでは、最良設定でも
帯の前景画素の半分が純粋な背景だった。**

そこで帯の中を 3 段で解き直す。

1. **縁の再分類**（`--no-reclassify` で切る）— 帯の中の二値画素を、局所の前景色と
   背景色に対する**散らばりで正規化した 2 択**で塗り直す。前景なのに背景寄りなら
   背景へ、背景なのに前景寄りなら前景へ。**判定は `mask.rim_contamination` と
   まったく同じ定義で、決められない画素は触らない。** これが「輪郭に張り付いた繊維」
   を落とす段で、正解側の縁の汚染（帯のうち真に背景だった割合）を下げる
2. **色の門つき平滑化**（`--smooth-contour 0` で切る）— 帯の中でメディアンを掛け、
   **変化した画素のうち色が変化に矛盾するものを元に戻す**。幅 3px のストラップ
   （商品色）はメディアンで消えても色の門で戻り、織り目の粒（背景色）は戻らない。
   フィルが背景と決めた画素を形の多数決で前景へ戻すことはしない——`--seal` が
   「塞がない」と約束した幅の隙間が、それで塞がってしまうためである
3. **guided feathering**（`--matting projection` で切る）— 射影のアルファを入力、
   線形 RGB の元画像を案内画像として、カラー guided filter を帯に掛ける。**均す
   強さは窓の中の背景の分散から決まる**ので、織り目の縁は案内として効かず、商品の
   輪郭だけが効く。きれいな背景ではほぼ恒等になる。輪郭の粗さ（`contour_roughness`）を
   下げるのが主にこの段である

1 と 2 は形が動かなくなるまで繰り返す（上限 4 回）。1 回で剥がせるのは帯幅ぶんだけ
だが、実写ではマスクが 20px 級はみ出す場所があり、その状態では「帯の外の前景」
そのものが繊維なので判定が効かない。剥がすほど判定が効くようになる。**商品の側は
削れない**——色の門が真の輪郭で止める。

**「帯の外を触らない」はパスごとの性質なので、累積には別の上限を置く。** 元の二値
輪郭から `2 × 帯幅の上限` より深い画素は塗り直さない。これが無いと、商品に彫られた
背景色のチャネルをパスごとに奥へ進める。

`--smooth-contour` は**長辺 1000px 換算**の半径で、上限は 16。実際に効いた実寸の
半径は結果の `settings.smooth_radius_px` に出る（20MP では指定値の 5 倍前後、
48px で頭打ち）。**要求値と実効値が食い違いうるものは、両方を結果に出す。**

`--seal` が塞いだ隙間は**帯から外す**。戻すだけでは、続く射影アルファが同じ色を見て
「純粋な背景」と答え、0 で塗り潰してしまう。空間的な指示（`--trimap` などで確定
させた画素）も同じ理由で帯から外れる——**指示は色より強い**という規約の帰結である。

合成画像（真の被覆率が分かるもの）での実測。`assisted` は kiri 自身の警告の hint に
従って到達する設定（`--bbox` + `--tolerance 60`）である。

| シーン | 輪郭が真の位置からずれた量(px@1000) | 帯のうち真に背景だった割合 |
|---|---|---|
| 不織布 + 黒商品 | 18.4 → **6.0** | 0.512 → **0.224** |
| 照明勾配の不織布 + 黒商品 | 10.2 → **1.1** | 0.256 → **0.066** |
| 不織布 + 3px ストラップ | 33.4 → **13.9** | 0.589 → **0.269** |
| 不織布 + 柔らかい輪郭 8px | 20.8 → **7.8** | 0.498 → **0.183** |
| 暗い机 + 白商品（既定値のまま） | 3.9 → **0.4** | 0.031 → **0.000** |

実写 24.5MP（白い不織布の上の黒いリモコン、最良設定）では `contour_roughness`
0.391 → **0.245**、`rim_contamination` 0.096 → **0.061**。納品寸法
（`--canvas 1000 --flatten`）を 3 倍に拡大すると、上辺に並んでいた黒い突起が消え、
輪郭が直線に戻る。**ただし警告は両方とも消えていない。** 残った汚染の 77% は
輪郭から 0〜2px——帯のまっただ中——にあり、足りないのは帯の広さではなく輪郭
そのものの位置である（深さ別の内訳は docs/design.md 4.10）。

**払っているものもある。** 合成シーンでは、淡色商品（輪郭 ΔE 9.5）の削れが
1.9% → 3.0%、織り目の上の淡色商品の `alpha_mae` が 0.041 → 0.072、実写背景の
`alpha_mae` も 0.009 前後増える。輪郭の位置を稼ぐために階調をいくらか平らにして
いるということで、**きれいな素材では `--matting projection` のほうが階調は正確**
である（合成 S1 / S4 では 3 段とも恒等に近く、差は出ない）。

F と B の色差が小さい画素（淡い商品 × 白背景）では、射影も 2 択も雑音を拾うだけで
何も決められない。そこだけ従来の幾何的フェザー（`--feather`）へ落とし、**色が
何も言っていない画素は平滑化の対象からも外す**。全体を旧方式に戻すには `--no-refine`、
Phase 2 までの挙動に戻すには `--matting projection --smooth-contour 0 --no-reclassify`
を使う（後者は 1 バイトも変わらないことを確認してある）。

かかる時間は画像の面積ではなく**帯の広がり**で決まるので、**形状によって桁が
変わる**。12MP での追加コスト（`--no-refine` 比）は、角丸矩形のような滑らかな
シルエットで 0.6 秒、メッシュのように構造が帯より細い素材（櫛状 6px 周期）で
2.1 秒。後者は (1)(2) を 4 パス回すぶんで、帯が面ごと埋まると 1 パスの費用が
そのまま 4 倍になる。

## closed-form は織り目に効き、柔らかい輪郭には効かない

`--matting closed-form` は帯だけを未知にした連立方程式として解き直す（Levin の
closed-form matting）。**既定は `guided` のままである。** 効く素材が限られていて、
効かない素材では `guided` より悪いためで、**どちらが良いかは素材で決まる**。

狙って作ったのは「柔らかい輪郭（ぼけ 8px、半透明の袋、毛羽）を正確に解く」ことで、
**そこには当たらなかった。** 当たったのは別の場所である。

| 素材 | `guided` | `closed-form` | |
|---|---|---|---|
| 不織布 + 黒商品 | alphaMAE 0.090 / 輪郭誤差 4.23 / 粗さ 0.299 / 縁の汚染 0.121 | **0.066 / 0.73 / 0.052 / 0.011** | 警告 2 本が消える |
| 不織布 + 3px ストラップ | 0.094 / 9.52 / 0.402 / 0.133 | **0.074 / 1.53 / 0.137 / 0.016** | 警告 2 本が消える |
| 照明勾配の不織布 | 0.068 / 1.11 / 0.117 / 0.065 | **0.043 / 0.42 / 0.006 / 0.009** | 警告 1 本が消える |
| 落ち影のある合成 | 0.023 / 0.46 | **0.010 / 0.46** | |
| **柔らかい輪郭 8px** | **0.120 / 5.91** | 0.173 / 1.88 | alphaMAE は負ける |
| **淡色商品 × 織り目** | **0.072** | 0.136 | 負ける |
| **3px のストラップ（合成）** | **粗さ 0.082** | 粗さ 0.272 | しきい値 0.16 を越える |

**柔らかい輪郭で負ける理由は解き方ではなく帯幅である。** 帯の半径は 2〜3px しか
なく、帯の外は 0/1 に固定される。真の遷移が 8px にわたっていると、closed-form は
帯の中で 0 → 1 を完結させるしかないので、必ず真の傾斜より急になる。窓を 3×3 から
9×9 まで広げても 0.173 → 0.145 で頭打ちになり、`guided` の 0.120 には届かない。
`guided` は帯の中を平均するだけなので、急峻さの罰を受けない。

**3px のストラップでは輪郭が蛇行する。** 帯が芯まで埋めてしまうと境界条件の支えが
ほとんど無くなり、粗さが警告のしきい値（0.16）を越える。細い構造を持つ商品には
使わないこと。

使いどころは**織り目のある背景**（不織布・段ボール・畳）である。そこでは
`CONTOUR_ROUGH` と `RIM_CONTAMINATED` が `guided` では出続けるのに対し、
closed-form では合否をまたいで消える。

費用は小さい。24.5MP の合成シーン（柔輪郭 + 影）で **3.1 秒 / 671MB**、同じ画像の
`guided` が 3.3 秒 / 617MB なので、**時間は増えず常駐が +54MB** である。未知数は
24.5MP でも 25 万画素しかなく、共役勾配は 31 反復で止まる。較正シーン 21 点では
5〜97 反復で、上限 200 に触るものは 1 つも無い。触ったときは
`MATTING_NOT_CONVERGED` が出る。

## 所要時間とメモリ

Apple M4 Pro、release、`/usr/bin/time -l` の maximum resident set size。実写
（不織布の上のリモコン、`--tolerance 60`）を既定オプションで切り抜いた実測。

| 画像 | Phase 2 のバイナリ | 既定 | 増分 |
|---|---|---|---|
| 12MP（3000×4000） | 1.11 秒 / 369MB | 2.25 秒 / 364MB | +1.1 秒 / **−5MB** |
| 24.5MP（4284×5712） | 1.90 秒 / 757MB | 2.89 秒 / 790MB | +1.0 秒 / **+33MB** |
| 12MP の櫛（3px 歯 / 6px 周期） | 2.49 秒 / 425MB | 6.39 秒 / 465MB | +3.9 秒 / +40MB |

**メモリの増分は帯のタイルに閉じている。** 帯の外接矩形ぶんを確保していた頃は
24.5MP で +546MB（ピーク 1331MB）だった。いまは (b)(c) の積分画像を 128px タイルへ
切り、連結性の面を 1 画素 1 ビットで持ち、帯の面を作り直さず書き直している。
画像そのものの常駐（24.5MP で 700MB 級）は画素数に比例するので、そちらは変わらない。

`batch` は既定で CPU 数ぶん並列に走る。**同時に走る枚数 × 1 枚分**がピークになるので、
24.5MP を 10 並列で回すと 8GB 級を要求する。目安は「1 枚あたり 画素数 × 32 バイト」で、
12MP なら 400MB、24.5MP なら 800MB。メモリが足りない環境では `--jobs` で同時に開く
枚数を下げること（`--jobs 1` なら 1 枚分で収まる）。

**`--jobs` はスレッド数ではなく枚数である。** 1 枚の切り抜きの中でも、画素ごとに
独立な段（色の変換・候補の判定・マスクの組み立て）は並列に走る。メモリを決めるのは
同時に開く枚数のほうなので、`--jobs 1` は「1 枚ずつ・全コアで」という意味になり、
いちばん軽くていちばん速い構成である。

## 孤立ノイズは太さではなく面積で消す

`--cleanup` はオープニング（収縮 → 膨張）ではなく**連結成分の面積フィルタ**で効く。
オープニングは構造要素より細いものをすべて消すため、半径 2 は幅 5px 未満の構造を
無条件に落としていた。**ストラップ・持ち手・ケーブルといった商品の一部がそれで消える。**
面積で選べば、幅 3px のストラップは残り、3×3 のゴミは消える。

面積の下限は**解像度に比例させる**。ゴミの大きさ自体が解像度に比例するためで、
同じ被写体を 4 倍で撮れば、同じ大きさに見えるゴミは 16 倍の画素を占める。
`--cleanup` の値は「長辺 1000px 換算での半径 px」と読み、実際の下限は
`(2n+1)² × (長辺/1000)²` になる（長辺 1000px 以下では倍率 1）。20MP の不織布では
織り目の 1 粒が 150px² あり、固定の 25px² では一つも消えなかった。

穴埋め（クロージング）は行わない。前景は「外周から到達できなかった領域」として
定義されるので、到達できない穴はそもそも前景になっている。残るのは細い隙間を通って
外周とつながった領域だけで、それを埋めるのは形の改変にあたる。
