## 4.11 背景を「1 色」ではなく「照明場」として持つ

### なぜ 1 色では足りないか

紙や布のスタジオ背景には、照明の勾配・ビネット・しわが乗る。`uniformity` が
0.90 を下回る原因の多くは「単色でない」ではなく「**単色の背景に低周波の変動が
乗っている**」である。

実写（白い不織布の上の黒いリモコン、20MP）で測った。

| 背景 | 外周 ΔE p50 | 外周 ΔE max | 1px あたりの勾配 p50 |
|---|---|---|---|
| 原画 | 11.9 | 60 | 11.3 |
| ガウスぼかし r=4（織り目を消す） | 11.0 | 58 | 3.9 |

**織り目を消しても外周 ΔE は 11 のまま残る。** 残っているのは照明ムラとしわの
大域変動で、これを 1 色 + `--tolerance` で飲むには tolerance 60 が要った。60 は
淡色商品をまるごと飲む値で、実際 tolerance 70 では商品が削れた（前景比率 0.078）。
**「背景を消せる値」と「商品を残せる値」が両立しないのは、背景が 1 色だと
思い込んでいるからである。**

### 場の推定

1. 長辺が `FIELD_LONG_SIDE`（256）になる格子（20MP で 256×192）へ切る
2. セルごとに「既知の背景」画素の**中央値**（線形 RGB）を採る。既知の材料は
   外周の帯（短辺 3%）・`--bbox` の外側・確定背景・信頼度 High の `subject` の
   矩形を 5% 広げた外側の 4 つ。平均ではなく中央値にするのは、商品の縁が掛かった
   セルで平均が引きずられるため
3. **どの源から来た画素にも同じ色の門を掛ける**（次節）。1 色の中央値から
   `max(FIELD_GATE_FLOOR, FIELD_GATE_FACTOR × 外周 ΔE p50)` より遠い画素は
   材料にしない。門を通った帯の画素が `MIN_BAND_MATERIAL`（30%）を切ったら
   場そのものを諦めて 1 色へ落ち、`BACKGROUND_FIELD_SKIPPED` を出す
4. 標本がセル面積の 1/4 に満たないセルは「未知」とし、**正規化畳み込み**
   （既知の値と重みを同じ核でぼかし、値 ÷ 重み）で埋める。埋めた値は次の回の
   材料に戻し、全セルが埋まったあともさらに数回回して緩める
5. 既知のセルは毎回もとの中央値へ打ち直し、最後に σ = 1 セルで全体を均す
6. **1 回目のフィルの結果を材料に場を作り直し、もう一度フィルする**

推定は決定的で、乱択を使わない。**全解像度の表は作らない**——12MP の Lab の表は
72MB あり、フィルが持つ画素ごとの Lab と二重に積む余裕が無い。場は格子 +
双線形補間で都度引く。

### 埋め方を 2 度直した

最初の実装は「届いたセルから確定させ、届かなかったセルは σ を 2 倍にしてやり直す」
だった。**σ が変わった境目に場の段差が残る**——同じセルでも 1 回目に届いたか
2 回目に届いたかで別の核の答えになるためで、実測では 1px あたり ΔE 2.2 の跳ねが
出た。場の段差はそのまま色差の段差になり、フィルはそこで止まる。埋めた値を
次の回へ戻し、覆った後も緩めるようにして 0.37 まで落ちた（8bit へ丸める段だけ）。

σ そのものも 2 つの実測で挟んだ。

| σ | R7 defaults の輪郭誤差 | 20MP の場の推定 |
|---|---|---|
| 長辺/8 | **1.99** | 25.6 ms |
| 長辺/16 | 0.41 | 25.7 ms |
| 長辺/32 | 0.41 | 27.8 ms |
| 長辺/64 | 0.41 | 29.7 ms |
| 長辺/128 | 0.41 | **34.9 ms** |

下側は R7（照明勾配のある紙 + 黒商品）で、1/8 では核が広すぎて勾配を追いきれない。
上側は費用である——核が狭いほど前線が 1 回で進まず、埋め直しの回数が増える。
1/128 は 20MP で 34.9 ms かかり、予算の 30ms を超える。1/32 は両側から離れている。

**上側の根拠は入れ替わった。** 最初の較正では「1/16 の核が 2 色の段差を塗り広げ、
その帯がまとまった塊に見えて `subject` が誤って `high` を返す」を上限にしていたが、
主体の検出は 1 色の背景に対して行うと決めた（下の節）ので、**その測定は出荷コード
では再現しない**。費用のほうは誰でも測り直せる。

### 場の材料に掛ける色の門

**場は「物体を表せてしまう」。** 材料の第一は外周の帯なので、商品が画面の端で
見切れていれば帯の 1 辺がまるごと商品の内部になり、場はそこで商品の色を背景として
学ぶ。学んだ場の上では商品は背景と一致し、見切れた部分がまるごと消える。消えた
結果 `SUBJECT_TOUCHES_EDGE` も出なくなるので、**エージェントからは成功に見える**。

| シーン | 正しい前景比率 | 門なしの既定 |
|---|---|---|
| 白背景・下端で見切れ（商品が外周の 17.5%） | 0.3150 | **0.1713** |
| 同上・見切れが浅い版 | 0.1750 | **0.1000** |
| 画面外へ抜ける大きな物体 | 0.4461 | **0.1226** |
| 画面の 4 割を占める物体だけ | 0.4000 | **0.0202** |
| 4 辺へ抜ける大きな商品 | 0.8445 | **0.2917** |
| 照明勾配 + 下端で見切れ | 0.3150 | **0.1673** |

**外周の統計量で `auto` の切り替えを止めても解けない。** 「照明勾配 + 見切れ」
（uniformity 0.38 / 外周 ΔE p50 6.7）と R7（0.34 / 6.7）は区別がつかない。
効くのは場の材料そのものに門を掛けることだけで、1 色の中央値から遠い画素は
どの源（帯・`--bbox` の外・確定背景・2 回目のパスの背景）から来ていても材料に
しない。物体は 1 色の中央値から遠く、照明ムラは近い、という差だけを使う。

```
門 = max(FIELD_GATE_FLOOR 15, FIELD_GATE_FACTOR 2 × 外周 ΔE p50)
```

倍率 2 は「背景が自分で見せているばらつき（p90 は p50 の 2.2〜2.5 倍に来る）
までは材料に入れ、その外は物体とみなす」を意味する。下限 15 が要るのは、白背景に
見切れた商品という構図では p50 が 0.0 になり、倍率だけでは門が閉じきるためである。

掃引（6 シーン + R7 defaults + 実写リモコン bbox なし tol 20 + 実写キーボード）。

| 門 | 実写リモコン | 織り目の上の大きな物体 | R7 defaults |
|---|---|---|---|
| ≦ 6.7 | — | — | **輪郭誤差 48.1** |
| ≦ 20（倍率 1.85 未満） | **外周接触あり**（fg 0.221） | 物体は残る | 0.41 |
| 既定（リモコン 23.9 / 汚染 15） | 外周接触なし・fg 0.219 | 残る（0.4461） | 0.41 |
| ≧ 18（倍率 2.52 以上） | 外周接触なし | **物体が消える**（0.1068） | 0.41 |

**分けられない組が 1 つある。** 「下端に境界すれすれの帯」（背景に落ちた影、
ΔE 17.67）と「織り目の上の大きな物体」（ΔE 17.74）は 0.07 しか違わない。門を
18 まで広げれば影は吸えるが、同時に画面の 35% を占める物体が背景として学ばれる。
色差だけでは「背景に落ちた影」と「背景に置かれた物体」を分けられないので、
**物体を消さない側へ倒してある**——影が前景に残るのは `--bbox` 一つで解けるが、
消えた商品には誰も気づかない。Phase 4 の最初の版では影を吸えていたので、
**ここは機能が 1 つ減った**（合成シーン 1 枚ぶん）。

### 何に効かせ、何に効かせないか

効かせる先は 4 つ。`classify`（画素ごとの背景色）、`is_shadow`（照明の勾配は
「その場の背景より暗い」にならないので、勾配を影と取り違えなくなる）、
`core_tolerance` の基準（外周 ΔE の p90 → **場に対する残差**の p90）、そして
`refine` の受け皿（確定背景が窓に 1 つも無いときの B と、代役前景の順位付けの基準）。

**`subject` には効かせない。** 設計では「背景から遠い」も場に対して測るつもり
だったが、較正表（13 シーン）で 2 件が裏返った。

| シーン | 1 色 | 場 | 正しい判定 |
|---|---|---|---|
| 画面の 4 割を占める物体だけ | low | **high** | low |
| 暗い机の上のキーボード（実写） | low | **high** | low |

どちらも**商品が外周の帯を大きく占める**画像である。場は帯から作るので、そこで
商品の色を「背景」として学んでしまう。すると商品は背景と一致し、残った別のもの
（2 色の境目の帯、机の映り込み）が「まとまった主体」に見えて `high` で返る。
`leftover_ratio` はこれを弾けない——取りこぼした物体は場の上では背景なので、
外に何も残らないからである。閾値だけを 1 色の分布に戻す案も試したが、今度は
織り目の上の汚染シーンが裏返った（low → high）。**場の側に手を入れて両方を通す形は
見つからなかったので、主体の検出は 1 色の背景に対して行う。**

### 効果と限界

| 素材 | 設定 | 1 色 | 照明場 |
|---|---|---|---|
| R7 照明勾配のある紙 + 黒商品 | 既定 | 前景比率 0.463 / 輪郭誤差 59.1 / rim 正解 0.570 | **0.375 / 0.41 / 0.000** |
| S13 照明勾配の背景 | 既定 | 0.410 / 9.77 / `HALO_REMAINS` | **0.375 / 0.46 / 警告なし** |
| 実写リモコン 20MP | bbox なし tol 20 | 外周接触あり | **外周接触なし / 0.219** |
| R1 不織布 + 黒商品 | 既定 | 0.610 / 131.2 / 0.926 | 0.437 / 108.6 / 0.860 |
| R2 照明勾配の不織布 | 既定 | 0.502 / 121.5 / 0.854 | 0.390 / 109.4 / 0.608 |
| R3 不織布 + 淡色商品 | 既定 | 0.206 / 119.7 / 0.999（削れ 100%） | 0.516 / 110.0 / 0.907（削れ 0%） |

**不織布（R1 / R2 / R5 / R6）は場を入れても切れない。** 残っているのは照明では
なく織り目で、これは堤防（4.3）の担当である。場は近づける（R2 の rim 正解
0.854 → 0.574）が、外周接触は解消しない。

### 費用

20MP で **場の推定 27.2 ms / 約 2MB**（予算 30ms / 5MB）。既知の画素が 1 つも
無いと言い切れるセルは画素を舐めずに飛ばすので、1 回目のパスの費用は画像の面積
ではなく帯の面積に比例する。

**色の門が費用の半分を占める。** 門を入れる前は 13.8 ms だった。門は帯の 200 万
画素（20MP、帯は短辺の 3%）に掛かり、素直に `delta_e_rgb` を呼べば 1 画素あたり
3 回の `cbrt` になる。6bit × 3 に量子化した表で区画ごとに 1 度だけ測り、門から
ΔE 8 以内の区画だけ正確に測り直す——**量子化しても答えは変わらず**、費用だけが
1/4 になる。

**2 回目のパスは別勘定である。** フィルをもう一度回すので、20MP の `cutout()`
全体で **+312 ms**（3021 → 3332 ms、+10%）。2 回目のパスの材料は画素ごとの表
（1 画素 1 バイト、20MP で 19MB）で、場を作り終えたら手放す。予算はここに
掛かっていないが、黙って払う額ではない。1 回目だけで止めると R7 の輪郭誤差は
0.41 → 13.2、rim 正解は 0.000 → 0.241 に戻るので、**この費用は R7 を解くために
払っている。**

12MP では場の推定 19.1 ms / 約 2MB、`cutout()` 全体で +177 ms（1815 → 1992 ms）。

### R2 の `defaults` は堤防では切れない（測り切った）

Phase 13（照明場）が R7 を既定値のまま切れるようにした後、不織布の R2 だけが
「場で近づくが解消しない」状態で残った。原因を**織り目＝堤防（4.3）の担当**と
見立てていたが、掃引で外れていた。

R2 の `defaults` に `--edge-threshold` を 0〜60 まで振る（`--tolerance` も
12 / 20 / 30 の 3 通り）。

| `--edge-threshold` | 前景比率 | 輪郭誤差 | rim 正解 | 外周接触 |
|---|---|---|---|---|
| 0（堤防を切る） | 0.3904 | 108.26 | 0.609 | あり |
| 8（既定） | 0.5026 | 122.38 | 0.839 | あり |
| 15 | 0.3930 | 110.57 | 0.644 | あり |
| 25 | 0.3909 | 111.33 | 0.616 | あり |
| **29.9（自動調整が選ぶ値）** | **0.3903** | **109.39** | **0.608** | **あり** |
| 40 | 0.3899 | 107.73 | 0.601 | あり |
| 60 | 0.3904 | 108.26 | 0.609 | あり |

**自動調整が選ぶ 29.9 と、最良（40）の差は輪郭誤差で 1.5% しかない。** 堤防を
切っても、青天井にしても、輪郭誤差は 107〜122 の帯から出ない。既定の 8 だけが
明確に悪い（壁になる）が、それは自動調整が既に直している。R1 / R5 / R6 でも
同じ形で、堤防はこの素材の残差を動かす軸ではない。

動く軸は `--tolerance` のほうである（堤防は自動、矩形なし）。

| `--tolerance` | 前景比率 | 輪郭誤差 | rim 正解 | 外周接触 |
|---|---|---|---|---|
| 12（既定） | 0.3903 | 109.39 | 0.608 | あり |
| 30 | 0.3861 | 95.27 | 0.531 | あり |
| 45 | 0.3822 | 72.42 | 0.420 | あり |
| 60 | 0.3781 | 35.39 | 0.248 | あり |
| 80 | 0.3769 | 24.28 | 0.174 | あり |
| **矩形あり + 60（`assisted`）** | — | **1.11** | **0.065** | なし |

単調に良くなるが、**矩形なしでは `assisted` に 20 倍の差で届かない**（24.3 対
1.11）。外周接触も許容量では消えない。正解の被覆率（0.375）に対して前景比率は
どの許容量でも 0.377〜0.390 とほぼ合っているので、**足りないのは面積ではなく
位置**である。

**逃げ道は 2 つとも立っている。** R2 の `defaults` は `BBOX_RECOMMENDED` を
信頼度 High の矩形（正規化 [0.202, 0.110, 0.798, 0.870]、捕捉率 0.881、
取りこぼし 0.071）とともに出す。その矩形を当てれば輪郭誤差 1.11 に落ちる。
`--optimize` は矩形と許容量 45 を自分で選んで同じ 1.11 に届く（4.13）。
**素材の限界として文書化し、堤防側の残件は閉じる。**

## 4.15 背景をグレーカードとして色を正す

EC の素材は「白い紙・布の上に商品を置いて撮る」形がほとんどである。つまり**画面の
大半に、本当は無彩色で、本当は明るいはずの面が写っている。** それをグレーカードと
して読めば、カメラのオートホワイトバランスが外した色かぶりと、露出が外した明るさを、
線形 RGB の対角ゲイン 1 回で正せる。`--white-balance auto` / `--exposure auto` が
それを行う（どちらも既定 off）。

### なぜ既定 off か

**1 枚の画像からは「色のある背景」と「色かぶりした中性背景」を区別できない。**
青い背景紙の上の商品と、青くかぶった白背景の商品は、画素としては同じものである。
前者に白点を当てれば背景は灰色になり、商品の色は青の補色へ転ぶ。中性度の門
（`NEUTRAL_CHROMA_MAX`）はその事故を狭めるだけで、無くせない。

加えて、**切り抜きの指標が良くなる保証が無い。** 実写 2 枚に `--white-balance auto`
を当てた前後（Apple M4 Pro、既定の他の設定）:

| 素材 | 指定 | `color.gain` | `clipped_ratio` | `foreground_ratio` | `halo_ratio` | `separability` | `contour_roughness` |
|---|---|---|---|---|---|---|---|
| remote.jpg (24.5MP) | なし | — | — | 0.2492 | 0.1275 | 19.597 | 1.2393 |
| remote.jpg | `--white-balance auto` | [0.943, 1.007, 1.120] | 0.015 | 0.2619 | 0.1265 | 19.227 | 1.2095 |
| remote.jpg | `--exposure auto` | [1, 1, 1]（断った） | 0.0 | 0.2492 | 0.1275 | 19.597 | 1.2393 |
| keyboard.jpg (12.2MP) | なし | — | — | 0.6497 | 0.1461 | 24.573 | 0.8132 |
| keyboard.jpg | `--white-balance auto` | [0.905, 1.019, 1.149] | 0.0083 | 0.6531 | 0.1385 | 23.823 | 0.7588 |
| keyboard.jpg | `--exposure auto` | [1, 1, 1]（断った） | 0.0 | 0.6497 | 0.1461 | 24.573 | 0.8132 |

**良くなる指標と悪くなる指標が混ざる。** `halo_ratio` と `contour_roughness` は
どちらの素材でも下がり（remote で 0.1275 → 0.1265 と 1.2393 → 1.2095）、
`separability` はどちらでも下がる（＝悪化。remote で 19.60 → 19.23）。
`foreground_ratio` は両方で 1 ポイント強増える。**得るものが「見た目の色が揃う」に
限られ、失うものが「背景が色紙だった場合の破壊」である段は、利用者が求めたときだけ
動くべきである。** `--shadow` / `--segment` と同じ規約で、渡さない実行では出力画像も
結果 JSON も 1 バイト変わらない（`off_does_not_change_a_single_byte`）。

`--exposure auto` は実写 2 枚のどちらでも当たらなかった。remote は白飛びの門、
keyboard は明度の下限で断られる——**それが正しい**（下の「5 つの定数」を参照）。

### 置き場所は切り抜きの前

色かぶりと露出のずれは、切り抜きの**判定そのもの**を狂わせる。背景と商品の ΔE、
外周のばらつき、`separability`——どれも色の上で測る値なので、正す前に測った数値と
正した後に測った数値は別物である。後から画素だけ直しても、マスクは狂ったままの色で
引かれている。

そこで `cutout` の `load` 直後・`segment` 推論より前に置き、**以降のすべて（モデルの
推論・背景の見立て・subject・`--optimize` の探索・切り抜き・診断）を正規化後の画素で
測り直す。** 持ち回している見立て（`BackgroundSeen`）も正規化後の画像から作られる。

推定に使う背景の見立てだけは**正規化前の画像から 1 度だけ**測る（正規化後に測り直せば、
当てたゲインぶんだけ白点が動いて意味を失う）。`--bbox` と空間的な指示はその前に
解けているので、それを材料に入れた照明場を使える。

**off の実行ではこの見立てを 1 度も測らない。** 測れば費用が増え、乱れれば既存の
数値が動く。既定（両方 off）では新しいコードを 1 行も通らない。

実装は `src/color/normalize.rs` に置いた。`cutout/` ではなく `color/` なのは、これが
切り抜きの一部ではなく切り抜きの前に画素を直す段だからである——ICC 変換（3.5）と
同じ「入力の色を素直な形に揃える」仕事の続きにあたる。

### 白点

材料は `BackgroundAnalysis.field` である。場（格子）があるなら**セルの線形 RGB の
チャンネルごとの中央値**、1 色モデルならその 1 色を線形化した 1 点で、どちらから
測ったかは `color.source` が `field` / `flat` として返す。

**外周の帯の中央値（`background.rgb`）では代われない。** 帯は商品が大きく写った画像で
商品の色を混ぜるのに対し、格子セルは「ここは背景だ」と言い切れる画素だけから
作られている（4.11 の色の門）。中央値を採るのは、照明の落ちた隅のセルや取りこぼした
商品のセルに引っ張られないためである（平均だと引っ張られる）。

ゲインは**輝度を変えない** von Kries である:

```
Y   = 0.2127 Wr + 0.7152 Wg + 0.0722 Wb    （linear_to_lab とまったく同じ行）
g_c = Y / W_c                               (c = r, g, b)
```

これで白点 W は (Y, Y, Y) の無彩色へ移り、露出は動かない（露出は次の節の仕事で、
段を分けておかないと「色かぶりを直したら明るくなった」が起きる）。**係数を 0.2126 と
丸めて書き写さない**——`L*` を出した行列と最下位桁が食い違い、「白点を当てても輝度は
変わらない」という約束が 1 ビット崩れる。

中性度は Lab の彩度 `C* = hypot(a*, b*)` で見る。`color.white_point_shift` が返すのは
「白点と**同輝度の無彩色**との ΔE76」で、**これは C* と同じ数である**——(Y, Y, Y) は
Lab で a\* = b\* = 0 かつ L\* が白点と一致する（XYZ 行列の各行の和がちょうど
白色点の XN / YN / ZN なので、pivot の引数が 3 つとも同じ値になる）。1 つの数を門と
報告の両方に使うのは、**門が何を見たのかを利用者が読めるようにする**ためである。

### 露出

背景をグレーカードとして使い、その輝度を狙いの明度 `EXPOSURE_TARGET_L` へ運ぶ
スカラー `k = Y_target / Y` を掛ける。`color.exposure_stops` は `log2(k)` で、
**正なら明るくした、負なら暗くした**——正規化は持ち上げるだけの段ではない。

### 5 つの定数と較正

較正の材料は 32 点（合成 10 点 + 既存の S シーン 13 点 + R シーン 7 点 + 実写 2 枚）で、
入口は `tests/color_normalize.rs` の `print_the_calibration_table`（`--ignored`）である。
実写は `KIRI_BENCH_DIR` に置く。**表は `cutout` と同じ読み込み経路（ICC → sRGB）を
通す**——`image::open` で素通しすると白点が実行と食い違い、remote.jpg では C\* が
4.2 と 4.8 に分かれた。

#### `NEUTRAL_CHROMA_MAX` = 20.0（白点を当ててよい彩度の上限）

| 素材 | C\* | 20 での判定 |
|---|---|---|
| 合成の白背景 (248,248,247) / 一様グレー | 0.0〜1.0 | 当てる（ただしゲインはほぼ恒等） |
| 実写 keyboard.jpg（暗い机） | 3.3 | 当てる |
| 合成の織り目 (177,174,167) | 4.0 | 当てる |
| 実写 remote.jpg（暖色寄りの白い不織布） | 4.8 | 当てる |
| R1〜R7（実写の布・机から作った合成） | 4.5〜7.5 | 当てる |
| 合成の暖色かぶり（ゲイン 1.10/1.00/0.88） | 7.2 | 当てる |
| 合成の青背景 (60,110,200) | 53.5 | **断る** |
| 合成の緑背景 (70,170,90) | 56.9 | **断る** |

**通す側の最大が 7.5、断る側の最小が 53.5** なので、窓は (7.5, 53.5) と広い。
7.2 以下に下げると**この段が直したい相手（暖色かぶり）そのものを断る**。53.5 以上に
上げると**色紙を中性化してしまう**。境目の位置に敏感ではないが、**窓の下端寄りに置く**
——上へ寄せて起きる事故（色紙の破壊）は戻せず、下へ寄せて起きる事故（直せる素材を
断る）は警告を読んで `off` にすれば済むからである。

#### `EXPOSURE_TARGET_L` = 96.0（背景を置きたい明度）

| 狙い L\* | sRGB | 白背景 248 の行き先 | きれいな S シーンの clip | 何が裏返るか |
|---|---|---|---|---|
| 92 | 232 | 238 | 0.00000 | 白背景が目に見えて暗くなる。織り目の S11 が clip 0.00082 で予算を通ってしまう |
| **96** | **243** | **245** | **0.00000** | — |
| 98 | 250 | 250 | 0.00001〜0.00146 | 合成の暖色かぶりが clip 0.625 で断られる（狙いが高いぶん持ち上げ量が増える） |
| 100 | 255 | 255 | 0.31〜0.62 | 全素材が白飛びで断られる（段が死ぬ） |

純白に置けないのは、背景のノイズ（±1.5 程度）と JPEG の振幅がそのまま 255 を
越えるためである。**96 だけが「直すべきものを直し、壊すものを壊さない」側に全部
収まった。**

#### `EXPOSURE_MIN_L` = 60.0（露出を当ててよい明度の下限）

この門が**単独で効く帯は狭い。** 狙いが L\* 96 なので L\* 54.6 を下回る背景に要る
ゲインは 2 段（`MAX_GAIN`）を越えて範囲の門が閉じ、実写・織り目の素材はどれも
自分の明るい部分が飛ぶので白飛びの門（`CLIP_BUDGET`）が閉じる。**残るのは
「一様で、暗く、商品も暗い」素材だけ**で、そこだけはこの門しか止められない。

| 素材（一様・ノイズなし・黒商品） | L\* | 要るゲイン | clip | この門が無いと |
|---|---|---|---|---|
| グレー 140 | 58.3 | 3.43 | 0.00000 | **中間グレーの台紙が白い紙になる** |
| 露出不足の白紙 190 | 77.0 | 1.75 | 0.00000 | 正しく +0.8 段だけ持ち上がる（通したい） |

窓は (58.3, 77.0]。**下端寄りの 60 に置く。** この帯に住んでいるのは「露出を外した
白い紙」で、この段が直したい相手そのものである——上へ寄せると直せる素材を減らす
だけになる。

#### `MAX_GAIN` = 4.0（合成ゲインに許す倍率。下限はその逆数）

4.0 は 2 段。**他の門との関係を測った。** 露出に許される最大のゲインは
`EXPOSURE_MIN_L` (60) から `EXPOSURE_TARGET_L` (96) までの 3.18 倍で、白点のゲインは
C\* が上限 (20) のときでも 1.3 倍前後にとどまる。掛け合わせてようやく 4.1 に届くので、
**この門が閉じるのは 2 つの段が同時に効いた極端な組み合わせだけ**である。較正の 32 点
では 1 枚も届かなかった（要るゲインの最大は keyboard.jpg の 13.66 だが、そちらは
`EXPOSURE_MIN_L` が先に閉じる）。**それでも置く**——白点の材料が真っ黒（線形で 0）だと
商が無限になり、この門だけがそれを止める。

#### `CLIP_BUDGET` = 0.03（新たに白へ飽和させてよい画素の割合）

**指示書の初期値 0.001 では段が実写で 1 度も動かなかった。** 値を上げたのはそれが
較正で分かったからである。狙い L\* 96 での実測:

| 素材と段 | 当てようとしたゲイン | clip | 当てたいか |
|---|---|---|---|
| きれいな白背景 S1〜S10 / 合成の中性 226 / 暖色かぶり / 一様 190 の露出 | 0.96〜1.75 | 0.00000 | はい |
| 実写 keyboard.jpg の白点 | [0.905, 1.019, 1.149] | 0.00830 | **はい** |
| 実写 remote.jpg の白点 | [0.943, 1.007, 1.120] | 0.01500 | **はい** |
| 照明勾配の背景 S13 の露出 | 1.075 | 0.06048 | いいえ |
| 織り目 S11 の露出 | 2.122 | 0.11371 | いいえ |
| 実写 remote.jpg の露出 | 2.141 | 0.33394 | いいえ |
| 実写 keyboard.jpg / R4（暗い机）の露出 | 7.2〜13.7 | 0.63〜0.81 | いいえ |

**窓は (0.015, 0.060) である。** 0.001 に置くと、実写 2 枚では**白点のわずかな補正
（青を 12% 上げるだけ）まで断られる**——24.5MP では布のハイライト 1.5% が 255 に
達するので、予算を 0.1% に置けば必ず越える。それでは「背景を無彩色に戻す」という段
そのものが実写で 1 度も動かない。0.03 を採るのは、通したい最大（remote の白点 0.015）の
2 倍あり、断りたい最小（S13 の露出 0.060）の半分だからである。

**飛ぶ 3% は「もともと白に近かった画素」である。** 白点のゲインは弱いチャンネルを
1 割ほど持ち上げるだけなので、255 に達するのは既に 250 前後だった画素に限られる。
露出の持ち上げが飛ばすのは**背景そのもの**で、そちらは戻せない——2 つを 1 つの予算で
分けられるのは、後者の clip が桁で大きいからである。実際に飛んだ量は
`color.clipped_ratio` が返す。

**数えるのは「線形値が 1.0 を超えた画素」である。** 8bit へ丸めた結果が 255 になった
画素とは厳密には一致しない——`linear_to_srgb_u8` は線形 0.9923 以上を 255 へ丸めるので、
超えていないのに 255 になる画素が存在する。**予算が守りたいのは「情報が失われた量」**で、
上限を超えた分は二度と戻らないのに対し、丸めで 255 に乗った画素は元の値をまだ保っている
（逆向きのゲインで戻せる）。結果 JSON の `color.clipped_ratio` も同じ定義である。

**もともと 255 に張り付いていたチャンネルは数えない。** 張り付きは元の露出の結果で、
正規化の責任ではない。数えると、白飛びした素材では門が常に閉じて色かぶりも直せなくなる。
判定は画素単位（1 チャンネルでも新たに飛べば 1 画素）で、チャンネル単位にすると
分母が 3 倍になり、予算の意味が「飛んだ画素の割合」から「飛んだ成分の割合」へ
静かに変わる。

#### 「当てない」の判定は幅ではなく表で決める

**最初は `|g - 1| <= 1e-6` という幅で見ていた。それは 8bit の分解能より 3 桁細かかった。**
実測すると、256 通りのどれかを動かす最小の相対変化は**下げ側で 0.4455%、上げ側で 0.4483%**
（最初に動くのは v=255 と v=254）である。幅で見ていた頃は `gain = 1.003` のような実行が
`status: applied` を名乗りながら画素を 1 つも動かさず、`round4` の報告は `[1, 1, 1]` に
なっていた——「applied なのに恒等ゲイン」である。

いまは**ゲインの 256 通りの表を作り、それが恒等かどうかを見る**（`GainTable::is_identity`）。
幅を決める必要がなくなり、`no_change`（直すものが無い）という語の意味にも忠実になる。
表は白飛びの数えと適用にも使う 1 つの表で、3 つを別々に持たないのは、片方だけ式を直した
日に「飛ぶと数えた画素が飛ばない」が起こりうるからである。

#### 門は公開する桁で判定する

中性度と明度の門は、**結果に出す桁（小数第 1 位）へ丸めた値で切る。** 生の値で切ると、
C* 20.04 を「彩度 ΔE 20.0 が上限 20.0 を超えるため」と報せる実行が作れる——message と
`data` が矛盾し、受け手は自分で同じ判定を書けなくなる。**公開した数が契約であり、
その数で門が閉じたと言えるほうが正しい。** 較正した 32 点ではどの判定も裏返らない
（境目に最も近い素材でも C* は 7.5 と 53.5、L* は 58.3 と 77.0 で、丸めの 0.05 では
動かない）。

### 門は段ごとに落ちる

判定の順は **白点の門 → 露出の門 → 合成ゲインの門（範囲・白飛び）** である。
白点だけが落ちて露出が当たる、その逆、両方落ちる、の 4 通りがすべて起こる。

**合成で初めて越えることがある。** 白点だけ・露出だけなら収まるのに掛け合わせると
上限を越える／白が飛ぶ、という組み合わせが実在する。そのとき落とすのは
**実際に門を押し出している段**である。

#### 最初は「露出から先に諦める」と決め打ちしていた（間違いだった）

根拠にしていたのは「白点は絵を明るくしないので白飛びの原因は露出のほう」という主張
だが、**これは前提が間違っている。** 輝度を変えない von Kries は輝度（係数つきの
重み付き和）を保つだけで、**必ず弱いチャンネルを持ち上げる**——暖色の背景なら B を
1 割から 3 割上げる。

そして露出が暗くする側（`k < 1`）のとき、決め打ちは**証明可能に逆効果**になる。
白飛びの判定は各チャンネルについて `lut[v] * g > 1.0` なので `g` について単調
非減少で、**1 以下のゲインは新しい飽和を 1 画素も作れない。** つまり `k < 1` の合成は
白点単独より必ず飛ぶ量が少ない。露出を先に落とせば次の周回は**より飛ぶ**ゲインを
評価することになり、必ず断られ、最後に白点も落ちて何も当たらない。

実機で再現した（背景 255,245,215 の 400x400 に 252,252,252 の面を置いた画像）:

| 指定 | 直す前 | 直した後 |
|---|---|---|
| `--exposure auto` 単独 | applied / gain [0.984, 0.984, 0.984] / stops -0.023 | 同じ |
| `--white-balance auto --exposure auto` | **skipped / gain [1, 1, 1] / 警告 2 本** | applied / gain [0.984, 0.984, 0.984] / stops -0.023 / 警告 1 本 |

**渡した段が増えたせいで別の段が死ぬ**という、読みようのない振る舞いだった。
hint も嘘をついていた——「背景が明るすぎて持ち上げる余地がありません。`--exposure off`
で色かぶりだけを直すか」は、下げる指示に対して意味を成さないうえ、`--exposure off` に
しても白点は同じ理由で落ちるので色かぶりも直らない。

#### いまの規則

落とす段は次のように選ぶ（`stage_to_drop`）。**必ず「いま効いている」段を返す**
——効いていない段を落とすと、門が同じゲインを二度評価して止まらない。

| 状況 | 落とす段 | 根拠 |
|---|---|---|
| 片方しか効いていない | その段 | 選ぶ余地が無い |
| ゲインが有限でない | 白点 | `k` は有限な商から出る。無限の出どころは線形 0 のチャンネルを割る白点だけ |
| 白飛び・`k > 1` | 露出 | 両方が飽和を作っている。露出は 3 チャンネルすべてを動かすので寄与が大きい |
| 白飛び・`k <= 1` | 白点 | 単調性より、`k <= 1` は新しい飽和を作れない。飛ばしているのは白点 |
| 範囲・越えている向きへ露出が押している | 露出 | 同上（同じ向きなら露出を優先） |
| 範囲・押していない | 白点 | 越えさせているのは白点の側 |

同じ向きへ両方が押しているときに露出を優先するのは、寄与が大きいことに加えて
「色かぶりは直ったが明るさは元のまま」が人が読める結果になるからである（逆は
「明るくなったが色かぶりは残った」で、直したい順が逆転する）。

落ちた段は `WHITE_BALANCE_SKIPPED` / `EXPOSURE_SKIPPED` が `data.reason`
（`not_neutral` / `not_light` / `no_material` / `gain_out_of_range` / `would_clip`）と
数つきで言う。**両方落ちた実行では警告が 2 本出る。** 並びは諦めた順だが、
**どちらが先かは素材が決める**（持ち上げる側では `EXPOSURE_SKIPPED` が先、
下げる側では白点だけが落ちる）。**並びは契約ではない**ので、受け手は `code` で
分岐する。

`color.status` は 3 値で、**`no_change` と `skipped` を混ぜない**。前者は背景が
すでに中性で狙いの明るさだったということで直すものが無く、後者は門が閉じたという
ことである。**片方の段だけが落ちた実行は `applied`** ——絵は変わっているので、
落ちた段は警告のほうで読む。

### 費用

画素パスは 256 エントリの表を引くだけである（入力が 8bit で、ゲインがチャンネルごとの
定数なので `powf` を画素ごとに呼ぶ理由が無い。24.5MP では 7350 万回になる）。
白飛びの数えも同じ表で済む。Apple M4 Pro、`print_the_cost_on_a_large_image`:

| 素材 | 画素数 | 見立て（`analyse_background`） | 白飛びの数え + 画素パス | 合計 |
|---|---|---|---|---|
| keyboard.jpg | 12.2MP | 62 ms | 15 ms | 78 ms |
| remote.jpg | 24.5MP | 281 ms | 51 ms | 331 ms |

**費用の大半は見立てのほうである。** 画素パスは 24.5MP で 51 ms しかなく、切り抜き
全体（remote.jpg で 8.0 秒）に対して合計 4% にとどまる。rayon は入れていない
——並列化して縮まるのは 51 ms の側だけで、複雑さに見合わない。

### 限界

- **1 枚からは「色のある背景」と「色かぶりした中性背景」を区別できない。** 中性度の門は
  事故を狭めるだけである。背景が本当に色紙なら `off` のままにする（既定がそれである）
- **商品が画面の大半を占める素材では白点が商品の色を吸う。** 場の色の門（4.11）が
  防いでいるのは帯の汚染で、格子セルそのものが商品で埋まっている領域までは救えない。
  `--bbox` で商品を囲えば場の材料から外れる（警告の `hint` がそれを言う）
- **白点は対角ゲイン 1 回である。** 混色行列（CAT02 などの色順応変換）は使わない。
  対角で足りない素材——複数の色温度の光源が混ざった撮影——はそもそも「背景が
  無彩色である」という前提が成り立っていない
- **露出は背景を狙いに乗せるだけで、商品の明るさは見ていない。** 背景が白で商品が
  暗い素材では、商品はそのまま暗いままになる。トーンカーブを当てる段ではない
- **`--no-color-convert` と併せると、門は入力の色空間のまま測る。** Display P3 の素材を
  素通しした実行では C\* も L\* も P3 の数になり、中性度と明度の判定が sRGB のときと
  変わる。これは既存の ΔE 経路（`--tolerance` や背景推定）とまったく同じ前提だが、
  **この段は画素そのものを書き換える唯一の段**なので、併用するなら結果の `color`
  ブロックを確かめること
- **`color.source` と `background.model` は食い違うことがある。** 前者は正規化前の
  画素から測った見立て、後者は正規化後に測り直した見立てで、`auto` の分岐は
  `uniformity` で決まる。対角ゲインは Lab 距離を変えるので、境目の素材では裏返りうる

### 決め事の表

| 決めたこと | 根拠 |
|---|---|
| 既定 off | 1 枚からは色紙と色かぶりを区別できず、当てた側の破壊は戻せない。実写 2 枚で指標は良くも悪くもなる（上の表） |
| 切り抜きより前に置く | 色の上で測る判定（ΔE・外周のばらつき・`separability`）が正す前と後で別物になる。後から画素だけ直してもマスクは狂った色で引かれている |
| 見立ては正規化前の画像から 1 度だけ測る | 正規化後に測り直すと、当てたゲインぶんだけ白点が動いて意味を失う |
| off では見立てを 1 度も測らない | 既定の実行の費用と数値を 1 つも動かさないため |
| 白点は格子セルの中央値 | 外周の帯は商品の色を混ぜる。平均は照明の落ちた隅のセルに引っ張られる |
| 輝度を変えない von Kries | 段を分けないと「色かぶりを直したら明るくなった」が起きる。露出は別の段の仕事 |
| `white_point_shift` を C\* と同じ数にする | 門が見た数を報告にそのまま出す。2 つの数を並べると、どちらで断られたのか読み手が決められない |
| 合成の門では**押し出している段**を諦める | 白飛びの判定はゲインについて単調非減少なので、1 以下のゲインは新しい飽和を作れない。「露出から先」と決め打ちすると k<1 のとき証明可能に逆効果で、**両方 auto が片方だけより悪くなる**（上の再現表） |
| 警告の並びを契約にしない | どちらを先に諦めるかは素材が決める。受け手は `code` で分岐する |
| 「当てない」を幅ではなく表で判定する | 1e-6 の幅は 8bit の分解能（相対 0.4455%）より 3 桁細かく、「applied なのに恒等ゲイン」を作っていた |
| 門を公開する桁で判定する | 生の値で切ると message（ΔE 20.0）と `data`（20.04）が矛盾し、受け手が同じ判定を書けない |
| 有限でないゲインは警告の `data` に載せない | `serde_json` が `null` にするので、`color.gain` の `nullable: false` と食い違う。上限で丸めて載せると「その倍率を試した」という嘘になる |
| 数えるのは「線形の 1.0 を超えた画素」 | 守りたいのは情報が失われた量。丸めで 255 に乗った画素は元の値をまだ保っている |
| もともと 255 のチャンネルを数えない | 張り付きは元の露出の結果。数えると白飛びした素材で門が常に閉じる |
| 予算を 0.001 ではなく 0.03 に置く | 0.001 では実写 2 枚で白点の 12% の補正まで断られ、段が 1 度も動かない（較正で判明） |
| 画素パスを 256 エントリの表にする | 24.5MP で `powf` を 7350 万回呼ぶ理由が無い。結果は完全に同じで決定性も自明になる |
| アルファは触らず、透明画素の RGB も一様に掛ける | 入力はまだ切り抜かれていないので「透明だから背景」という意味が無い。飛ばす枝を作ると、指示用のアルファ付き画像を渡した実行だけ画素が揃わない |
| `settings` に `white_balance` を足さない | 白点と露出は**段ごとに落ちる** 2 段なので、要求値も `color` ブロックに閉じて `status` と同じ深さに並べる。単一のノブ（`--shadow` / `--reflect`）は逆に `settings` へ置く——規則は 4.16 の「`settings` に足すか、ブロックに持たせるか」にまとめた |
| `linear_to_srgb_u8` を `color/lab.rs` へ 1 本化 | 同じ式の複製が 3 つになると、片方だけ直した日に境界帯の 1 画素が静かにずれる。式と丸めは 1 ビットも変えていない（実写の出力 md5 で裏を取った） |
