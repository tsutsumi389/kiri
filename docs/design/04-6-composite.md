## 4.14 影を合成する

EC の納品先は「影なしの純白」と「自然な落ち影つき」の**両方**を求める。kiri は
4.4 で実写の落ち影を背景として消す側に倒したので、影つきを出す手段がここに要る。

### なぜ撮影時の影を残すのではなく、アルファから作り直すのか

`--shadow-tolerance 0` を渡せば撮影時の影は残せる。それでも合成を足すのは、
**残した影はばらつく**からである。撮影ごとに光源の向きと距離が変わり、商品の高さと
台の反射率でも濃さが変わる。並べたときに影だけが揃わないのは、`--fill-ratio` で
占有率を揃える動機とまったく同じ問題である。合成なら向きと濃さが指定どおりに揃い、
`batch` の spec に 1 行書くだけで数百点に同じ影が付く。

もう 1 つ、残した影は**切り抜きの品質指標を汚す**。影は前景として残るので
`foreground_ratio` に乗り、影と背景の境界が輪郭として `contour_roughness` に
数えられる。合成なら影は最後に足されるので、`mask` ブロックは商品だけを測ったままに
なる（後述の「商品の層を変えない」）。

### 箱型フィルタ 3 回でガウスを近似する

影の形は「アルファをずらして σ でぼかしたもの」である。素直なガウス畳み込みは
半径 3σ を舐めるので σ に比例して遅くなる。長辺 1000px 換算の σ 10 は 24.5MP
（長辺 5712）では 57px になり、分離可能にしても 2 × 171 × 24.5M 回の積和が要る。

代わりに**箱型フィルタを 3 回重ねる**（Kovesi, "Fast Almost-Gaussian Filtering"）。
σ と回数 n = 3 から整数幅 wl / wu と、幅 wl を使う回数 m を決める:

```
wIdeal = sqrt(12σ²/n + 1);  wl = floor(wIdeal)（偶数なら 1 引く）;  wu = wl + 2
m = round((12σ² - n·wl² - 4n·wl - 3n) / (-4wl - 4))
```

各パスは移動和なので画素あたり定数回の加減算で済み、**σ をいくつにしても所要時間が
ほとんど変わらない**。

**`cutout` 全体の `elapsed_ms` では測れない。** 切り抜きが 5 秒かかるので、その中の
0.1 秒台は実行ごとのばらつき（`--shadow off` で 4970〜5130ms、振れ幅 0.16 秒）に
埋もれる。合成そのものを `Instant` で挟んで測る
（`print_the_blur_cost_on_a_large_alpha`、24.5MP = 4284x5712、Apple M4 Pro）:

| 実寸 σ | `synth` 全体 | うちぼかし |
|---|---|---|
| 0（ぼかさない） | 45.1 ms | — |
| 57.12（既定の px@1000 で 10） | 158.9 ms | 約 114 ms |
| 228.48（px@1000 で 40） | 166.9 ms | 約 122 ms |

**σ を 4 倍にしてもぼかしは 7% しか増えない。** 増えた分は箱型の幅が広がったことで
移動和の初期化（窓の立ち上げ）が伸びたぶんで、画素あたりの仕事は変わっていない。
σ 0 の 45.1ms はずらし・不透明度・合成だけの費用で、ぼかしを入れない場合の下限に
あたる。素直なガウスなら σ 228 で半径 685px の畳み込みになり、桁が 2 つ変わる。

切り抜き全体（5.0 秒）に対して `synth` は 3% で、`--shadow off` との差は実行ごとの
ばらつきに埋もれる大きさである。

**幅は必ず奇数にする。** 偶数幅の箱型は重心が半画素ずれ、3 回重ねると影が
`--shadow-offset` の指定から 1.5px ずれる。単体テスト
（`the_shadow_sits_exactly_one_offset_away_from_the_product`）は、ぼかしありでも
影の重心が商品の重心 + オフセットから ±0.5px に収まることを見ている。

**整数演算にする。** アルファは u8、移動和は u32、各パスの割り算は四捨五入。
実数の総和は足す順序で最下位ビットが動くので、同じ入力から同じバイト列が出る保証が
崩れる。ICC の `powf`（3.5）と違い、ここは整数で閉じられる。

端の外側は 0（透明）として扱う。窓に収まった画素数ではなく**常に幅で割る**のが
その約束をそのまま算術にした形で、窓の実数で割ると画像の縁に沿って影が濃く残る。

### 商品の層は 1 画素も変えない

影のアルファが 0 の画素と、商品のアルファが 255 の画素は、`--shadow off` の出力と
**ビット一致**する。半透明の縁に影が重なる画素だけが straight alpha の「商品 over
影」を通る。

この約束のために、合成の算術を `transform/canvas.rs` の `composite` と共有している
（`over` を切り出した）。別々に書けば、同じ CLI の中に「半透明の縁で 1 ずつ食い違う
2 種類の合成」が並ぶ。1 の差は目には見えないが、md5 で非破壊を検査する立場からは
**壊れているのと同じ**である。

同じ理由で、`--canvas --flatten` の塗り順の組み替えは**下に敷く層があるときだけ**
通す（`--shadow synth` か `--reflect on`。4.16 で条件を広げた）。現状はキャンバス配置の
時点で下地を塗っているので、影があるときは「透明のまま配置 → 影 → 下地に載せる」に
組み替える。ここで書き出し側の `--flatten`（`image_io/save.rs` の `flatten_onto`、
四捨五入つき）に任せると、影のアルファが 0 の画素まで別の丸めを通り、約束が
成り立たなくなる。

**`synth` は「アルファを測る」`alpha` と「下へ敷く」`compose` に割ってある。**
反射（4.16）を併せると層の順が問題になるためで、**振る舞いは変えていない**
——`synth` はその 2 つを順に呼ぶだけになった。理由は 4.16 の「合成順のために影を
2 つに割った」にある。

### `--canvas` で影を切る

`--canvas` の配置（`fill_ratio` / `content` / `offset` / `scale`）は**影の有無で
変えない**。影のぶん商品を小さくする案も考えたが、採らなかった:

| 案 | 採否 | 理由 |
|---|---|---|
| 影がはみ出すなら切る（採用） | ○ | `--fill-ratio` は「商品がフレームの何割を占めるか」という納品先の規定そのもので、影の有無で動いてよい数ではない |
| 影を含めた外接矩形で `fill_ratio` を取る | × | 同じ設定を通した素材群で商品の大きさがばらつく。影の向きを変えただけで商品が動く |
| 影が収まるまで商品を縮める | × | 上と同じ問題に加え、`--shadow-offset` を大きくすると商品が際限なく小さくなる |

切ったことは `shadow.clipped` が言うので、収めたければキャンバスを広げるか
オフセットとぼかしを小さくする、という判断はエージェントの側でできる。

**`shadow.bounds` と `shadow.clipped` は別のキーにした。** ずらし量が画像より
大きければ影は 1 画素も残らないが、それは「影を置かなかった」（`--shadow-opacity 0`）
のではなく「全部はみ出した」である。1 つの `Option` に畳むと結果 JSON で両者が同じ形に
なり、指定が効かなかった理由を追う手段が消える。

### はみ出しは台ではなく、残ったインクで決める

`clipped` の判定は**最終の影のアルファ**で行う。真になるのは 2 つの場合で、
(a) ずらしただけで画像の外へ落ちた画素があった、(b) 外周の 1 列・1 行に影のインクが
残っている。(b) は「影がその先へ続いていた」ことの直接の証拠なので、ぼかしを
画像より大きな枠で計算し直さずに済む。

**最初は「ずらした矩形 + ぼかしの台（約 3σ）が縁を跨いだか」で決めていた。** これは
2 つの意味で嘘をついた。1 つは偽陽性で、箱型の台は σ の 3 倍あるのに裾は 8bit へ
丸めた時点で 0 になるため、**既定値でも `clipped: true` が出る**。既定で立つ旗は
読む側が無視するようになる。もう 1 つは `--shadow-opacity 0` で、影を 1 画素も
置いていないのに「はみ出した」と言っていた——`bounds` が `null` になる 2 つの理由を
`clipped` が分ける、という設計そのものが成立していなかった。不透明度が 0 なら
必ず偽にする。

### 決め事の表

| 決めたこと | 根拠 |
|---|---|
| 箱型 3 回でガウスを近似する | 24.5MP・σ 57px でぼかし 0.11 秒。σ を 4 倍にしても 7% しか増えない。素直なガウスは σ に比例し、σ 228 では桁が 2 つ変わる |
| `--shadow-blur` に上限（px@1000 で 1000）を置く | σ が最終画像の長辺に達すると影は一様に 0 まで薄まり、それ以上に意味のある結果が無い。加えて上限が無いと箱型の幅が u32 を溢れ、release では「ぼかしていないのに σ を報告する」嘘になる |
| `shadow.blur` に**実現した** σ を出す | 幅は奇数の整数しか取れず、σ が 0.5 を下回ると 3 回とも幅 1（恒等）に落ちる。要求値を返すと「ぼかしたと報告しているのに縁が段差」になる |
| `clipped` を最終のアルファで決める | 箱型の台は約 3σ あるので、台が縁を跨いだかどうかで決めると裾が丸めで消えている場合まで真になり、既定値で偽陽性が出る |
| 幅を奇数に揃える | 偶数幅は重心が半画素ずれ、3 回で 1.5px の位置ずれになる |
| 整数演算・四捨五入 | 実数の総和は足す順序で下位ビットが動き、決定性の約束が崩れる |
| 端の外側は 0、除数は常に幅 | 窓の実数で割ると画像の縁に沿って影が濃く残る |
| `over` を `canvas.rs` と共有する | 別々に書くと半透明の縁で 1 ずつ食い違い、「影のアルファ 0 の画素はビット一致」が成り立たない |
| 塗り順の組み替えは下に敷く層があるときだけ | どちらも `off` の実行にも通すと、合成と無関係な実行の出力が 1 ずつ動く（条件は 4.16 で `--reflect on` へ広げた） |
| `--canvas` は影のために商品を縮めない | `fill_ratio` は納品先の規定そのもので、影の有無で動いてよい数ではない |
| `mask` は影を足す前の商品だけで測る | 影で診断値が動くと、切り抜きが変わったのか影が乗ったのかを区別できない |
| px@1000 の基準は**最終**画像の長辺 | 元画像の長辺で換算すると、同じ指定が `--canvas` の有無で違う見た目を指す |
| `bounds` と `clipped` を分ける | 「影を置かなかった」と「全部はみ出した」が同じ形になると、指定が効かなかった理由を追えない |

## 4.16 反射を合成する

艶のある台に商品を置いた写真では、台に映った反射が「置かれている」ことの手がかりに
なる。4.14 の落ち影とまったく同じ立場の段で、動機も同じである——**撮影で作ると
ばらつく。** 台の反射率と光源の向きで濃さが変わり、並べたときに反射だけが揃わない。
合成なら `batch` の spec に 1 行書くだけで数百点に同じ反射が付く。

`--reflect on` / `--reflect-height`（px@1000）/ `--reflect-opacity` / `--reflect-gap`
の 4 つで、**既定は off**。off の実行では**新しい合成が 1 行も走らず**、成果物の画素は
1 バイトも動かない（増えるのは結果 JSON の `settings.reflect` の 1 行だけ）。
`resolve_reflect` は `None` を返して終わり、`Layers::any()` が偽になるので
`transform/reflect.rs` へは入らない——**「1 行も通らない」ではなく「合成へ入らない」**
が正確な言い方である（`settings.reflect` を綴る 1 行は必ず通る）。

### なぜアルファではなく画素を写すのか

影は「アルファをずらしてぼかし、`--shadow-color` で塗ったもの」である。反射に同じ形を
与える案——アルファだけを下へ敷いて単色で塗る——は採らなかった。**それは影の別名で
しかない。** 台に映るのは商品の色であって黒い塊ではなく、色を決めるノブ
（`--reflect-color`）が計画に無いのは、色を商品が決めるからである。

だから写すのは画素そのもの（RGB も）にした。商品のアルファの下端を基準線とし、
反射の j 行目は商品の `baseline - j` 行目の画素をそのまま置く（x はそのまま。
上下反転だけ）。straight alpha なので RGB は合成でも保たれ、`over` の `sa == 0` の枝を
通って**元の色がそのまま**出る。

**写せる行は基準線より上にある分しかない。** `--reflect-height` に商品より高い値を
渡しても、素材の無い行は空のままである。これは制限ではなく反射の定義そのものである。

だから **`reflect.height` は「敷いた行数」ではない。** あれは px@1000 の指定を実寸へ
掛け戻した数で、実際に占めた範囲は `reflect.bounds` が語る。2 つが食い違う理由は 3 つ
あり、どれも正常である: 写せる行が足りなかった／足元の数行が減衰の丸めで 0 になった／
画像の外へ出て切られた（3 つ目は `reflect.clipped` も真になる）。**掛け戻した数を
「敷いた行数」と名乗ると、受け手は差を不具合として読む。**

### 減衰は線形の 1 段だけ

反射の j 行目のアルファは

```
fade = opacity × (height − j) / height     … 行ごとに 1 度
a'   = round(a × fade)                     … 画素ごとに乗算 1 回と丸め 1 回
```

で、`opacity` は**商品に接する側**（j = 0）の濃さ、足元（j = height）で 0 になる。
**2 行に分けて書いてあるのは結合順が実装と同じであることを示すためである**
——`fade` を行ごとに 1 度だけ作るので、画素ごとに残るのは乗算 1 回と丸め 1 回だけに
なる。実数の総和を作らないので、足す順序で最下位ビットが動く余地が無い——4.14 の
「整数演算にする」と同じ約束を、同じ形で守っている。同じ入力から同じバイト列が出る。

**ぼかしも遠近変形も入れない。** `--reflect-blur` や台の角度は計画のフラグに無く、
入れれば箱型 3 回をもう 1 箇所で持つことになる。費用も増える一方で、EC の「台に
映った商品」は鏡面に近い台を前提にしているので、素の鏡像で用が足りる。

### 合成順のために影を 2 つに割った

計画の合成順は **下地 → 影 → 反射 → 商品**。`over` は結合的だが、**層が重なる順は
呼んだ順で決まる。** そして `shadow::synth` は「アルファを作る」と「商品の下へ敷く」を
1 関数で閉じていたので、そのまま反射を後から敷くと 2 つの誤りが同時に起きた:

1. 反射が影の**下**に入る（商品の真下が影の色のままになる）
2. `synth` を通した後の画像はアルファが混ざっているので、そこから鏡像を取ると
   **影を写した反射**になる。影は商品の下へずれているぶん、反射の中で二重に伸びる

そこで `transform/shadow.rs` を測る側と敷く側に割った（**振る舞いは変えていない**
——`synth` はその 2 つを順に呼ぶだけになった）:

```rust
pub fn alpha(product: &RgbaImage, spec: &ShadowSpec) -> (Vec<u8>, ShadowBounds);
pub(crate) fn compose(image: &mut RgbaImage, alpha: &[u8], color: [u8; 3]);
pub fn synth(product: RgbaImage, spec: &ShadowSpec) -> (RgbaImage, ShadowBounds);
```

`commands/cutout.rs` の `compose_layers` は (1) 商品だけから影のアルファを測り、
(2) 商品だけから反射を作って下へ敷き、(3) 測っておいた影をその下へ落とす。

**影だけの実行は `synth` を呼ぶのとバイト一致する**——同じ 2 つの関数を同じ順で
通るだけである。裏を取っているのは単体の
`splitting_synth_into_alpha_and_compose_changes_nothing` で、**等式そのもの**
（`synth` の出力と `alpha` + `compose` の出力が半透明の縁つきの素材でバイト一致）を
見ている。`--reflect off` と `--reflect` 無しを比べても、その 2 つは clap の既定値で
同一の引数値になるだけなので**同義反復**で、この等式の裏にはならない——CLI 側の
`an_explicit_reflect_off_does_not_disturb_a_shadow_only_run` が足しているのは
経路の広さ（`--canvas` あり / なし、`--flatten` あり / なし）のほうである。

`--canvas --flatten` の塗り順の組み替え（透明のまま配置 → 下の層 → 下地へ載せ直す）は、
条件を「影か反射のどちらかが on」へ広げた。両方 off の実行にも通すと、半透明の縁で
1 ずつ丸めが変わる（4.14 の同じ議論）。

### 商品の層は 1 画素も変えない

反射のアルファが 0 の画素と、商品のアルファが 255 の画素は、`--reflect off` の出力と
**ビット一致**する。合成の算術は 4.14 と同じ `transform/canvas.rs` の `over` を共有して
いる——別々に書けば「半透明の縁で 1 ずつ食い違う 3 種類目の合成」が生まれる。

実装は**その場で書く**（24.5MP の RGBA は 98MB あり、複製する理由が無い）。それが
安全なのは、**読むのは基準線より上の行だけ、書くのは基準線より下の行だけ**で、
2 つが交わらないからである。基準線より下は定義上アルファ 0 なので、そこでの `over` は
`sa == 0` の枝を通って反射の画素をそのまま置く。

`mask` ブロックの統計と診断値は**反射を敷く前の商品だけ**で測る。影と同じ理由で、
反射で数値が動くと切り抜きが変わったのか反射が乗ったのかを区別できなくなる。

### はみ出しと `clipped`

`--canvas` の配置は**反射の有無で変えない**。反射のぶん商品を縮める案は、4.14 の表と
まったく同じ理由で却下した（`fill_ratio` は納品先の規定そのもので、反射の有無で
動いてよい数ではない）。切ったことは `reflect.clipped` が言う。

判定は**最終の反射のアルファ**で行い、真になるのは (a) インクの出る行が画像の外へ
落ちた、(b) **下端の行**に反射が残っている、(c) **左右の 1 列**に反射が残っている、の
3 つである。

**(c) は「切られた」を意味しない。** 反射は横へ広がらないので、左右にインクが残るのは
**商品が画像の左右の縁に触れている**ということであって、反射が 1 画素も切られていなくても
真になる。`--shadow` の `offset (0, 0)` がまったく同じ振る舞いをするので規約をそちらへ
揃えたが、**偽陽性寄りであることは文面で言い切る**べきものである（README の反射の節と
`kiri schema` の `reflect.clipped` の notes が同じことを言う）。縦に収まっているかを
知りたい受け手は `reflect.bounds` の y2 を画像の高さと突き合わせればよい。
**`--reflect-opacity 0` と `--reflect-height 0` は敷かない指定なので必ず偽にする**
——`bounds` が `null` になる 2 つの理由（敷かなかった／全部はみ出した）を `clipped` が
分ける、という 4.14 の設計をここでも壊さないためである。

### 上限を置く 2 つの理由

`--reflect-height` / `--reflect-gap` の上限は px@1000 で 1000（= 最終画像の長辺
いっぱい）。高さは長辺ぶんあれば「素材のある行すべて」を必ず覆い切り、隙間は長辺に
達すれば必ず画像の外へ落ちるので、それ以上の指定に意味のある結果は無い。
`SHADOW_BLUR_MAX` と同じもう半分の理由——**上限が無いと算術に無理が掛かる**——も
同じで、`transform/reflect.rs` が走る行数を `baseline + 1` で抑えているのは二重の
備えのほうである（`MAX_BOX_WIDTH` と `SHADOW_BLUR_MAX` の関係と同じ）。

### 費用

**`cutout` 全体の `elapsed_ms` では測れない**（4.14 と同じ事情で、切り抜きの 5 秒に
埋もれる）。合成そのものを `Instant` で挟んで測る
（`print_the_reflection_cost_on_a_large_product`、24.5MP = 4284x5712、Apple M4 Pro）:

| 反射の高さ(実寸 px) | `synth` 全体 |
|---|---|
| 0（敷かない） | 2.8 ms |
| 857（px@1000 で 150 = 既定） | 9.4 ms |
| 2856（px@1000 で 500） | 14.7 ms |

**影より 1 桁安い。** 同じ機械・同じ寸法で `shadow::synth` は σ 57px で 148ms かかる
（ぼかしの 3 パスが画像全体を 6 回舐める）が、反射が舐めるのは敷く行だけである。
高さ 0 の 2.8ms は基準線を探す走査——商品の下端より下の透明な行を下から数えるぶん
——で、敷かない場合の下限にあたる。行数を 3.3 倍にしても 1.6 倍しか増えないのは、
この固定費が入っているためである。

切り抜き全体（5.0 秒）に対して 0.2% で、`--reflect off` との差は実行ごとのばらつきに
埋もれる。**rayon は要らない。**

### `settings` に足すか、ブロックに持たせるか

4.15 の表は「`settings` に `white_balance` を足さない——足せば既定の実行の JSON が
変わる」と書き、ここでは `settings.reflect` を**常に出す**。**矛盾ではないが、
4.15 が挙げた根拠に答えておかないと次に迷う**ので、規則をここで 1 度書く。

**キーが 1 つ増えるのは契約の破壊ではない。** `SCHEMA_VERSION` を上げるのは
「既存のキーの意味や型が変わったとき、つまり今までの読み方が誤読になるとき」だけで、
キーの追加はその内側にある（`report.rs` の `SCHEMA_VERSION` の doc）。`--shadow` /
`--rotate` / `--segment` はどれも `settings` に 1 行足して版を据え置いてきた。

分けているのは**そのノブが何段あるか**である:

| 形 | 置き場所 | 例 |
|---|---|---|
| 単一のノブ（off / on の 1 つの決定） | `settings` に要求値、効いた値はブロック | `shadow` / `rotate` / `segment` / **`reflect`** |
| 複数の段を 1 ブロックで語るもの | 要求値もブロックの中 | `color`（白点と露出の 2 段。段ごとに落ちる） |

`color` が例外なのは、**白点と露出が別々に落ちうる**ためである。要求値を `settings` に
2 行並べると、「両方 auto を頼んで露出だけ当たった」という状態を読むのに `settings` の
2 行と `color.status` の 3 値を突き合わせることになる。1 ブロックに閉じれば
`white_balance` / `exposure` / `status` / `source` が同じ深さに並ぶ。

**4.15 の「既定の実行の JSON が変わる」という言い方は、この規則の言い換えとしては
強すぎた。** 変わってよい（キーが増えるだけ）——変えたくなかったのは
`color` ブロックを 2 段のまま保ちたかったからである。反射は段が 1 つなので、
既定の形に合わせて `settings` へ置いた。

### 決め事の表

| 決めたこと | 根拠 |
|---|---|
| アルファではなく画素（RGB も）を写す | 台に映るのは商品の色である。単色で塗る形は影の別名でしかなく、`--reflect-color` を持たない計画の意図に反する |
| 減衰は線形 1 段、画素あたり乗算 1 回と丸め 1 回 | 実数の総和を作らないので足す順序に依存する余地が無い（4.14 の整数演算と同じ約束） |
| ぼかしも遠近変形も入れない | 計画のフラグに無く、箱型 3 回をもう 1 箇所で持つことになる。費用も増える |
| 合成順は 下地 → 影 → 反射 → 商品 | 商品に接して見えるのは反射である。影が上に来ると商品の真下が影の色で埋まる |
| 影を `alpha` と `compose` に割る | `over` は結合的でも層の順は呼ぶ順で決まる。加えて `synth` の後の画像から鏡像を取ると「影を写した反射」になる |
| 反射の材料は商品だけ | 影を写した反射は物理としても誤り（影は台の上にあり、台に映らない） |
| `over` を `canvas.rs` と共有する | 別々に書くと半透明の縁で 1 ずつ食い違う 3 種類目の合成ができ、「アルファ 0 の画素はビット一致」が成り立たない |
| その場で書く（複製しない） | 読むのは基準線より上、書くのは下で交わらない。24.5MP で 98MB の複製を避ける |
| 基準線は商品のアルファの下端 | 反射は「台に接している線」から始まる。外接矩形の左右は要らないので下から探す |
| 写せる行が足りなければ空のまま | 素材の無い行を作れば反射ではなく捏造になる。足りなかったことは `bounds` が言う |
| `--canvas` は反射のために商品を縮めない | `fill_ratio` は納品先の規定そのもの（4.14 の表と同じ） |
| `bounds` と `clipped` を分ける | 「敷かなかった」と「全部はみ出した」が同じ形になると、指定が効かなかった理由を追えない |
| 高さ 0 / 不透明度 0 は `clipped` を偽にする | 敷かない指定なので、はみ出しようがない。`--shadow-opacity 0` と同じ規約 |
| 上限は px@1000 で 1000 | 高さは長辺ぶんで素材を覆い切り、隙間は長辺で必ず外へ落ちる。それ以上に意味のある結果が無い。加えて上限は算術への第一の門である |
| `settings.reflect` を常に出す | 単一のノブは `settings` に置く（下の「`settings` に足すか、ブロックに持たせるか」） |
| 新しい warning code を足さない | はみ出しは `clipped` が真偽で言う。`--shadow` が同じ事実を `shadow.clipped` だけで語っているのに反射だけ警告を重ねると、同じ事実が 2 通りの形で配られる。既定 off の段で警告の出る条件が増えることの方が新しい契約になる（計画書 §7.4 の表から行を 1 つ消した） |
