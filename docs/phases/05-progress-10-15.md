# 5. 進捗 — Phase 10〜15

節番号は分割前のまま変えていない。`計画 §8.6` のような参照が他の節・src / tests から
150 箇所以上張られていて、**番号が識別子として働いている**からである。どの節がどの
ファイルにあるかは [実装計画](../implementation-plan.md) の索引で引く。

記号（`[x]` / `[ ]` / `※`）の意味は [§5 進捗](../implementation-plan.md#5-進捗) にある。

- [x] Phase 10: 境界の欠陥を測れるようにする
  - [x] `mask.contour_roughness` / `mask.rim_contamination` を足す。**旧来の
        指標（`halo_ratio` / `edge_width` / `separability`）は、実写の不織布で
        欠陥が目に見えて残っている画像を「合格」と呼んでいた。** 前者は絶対的な
        色差の基準が布のばらつきに負け、後者は遷移の幅しか見ないので蛇行に
        反応しない。較正と根拠は design.md 4.8
  - [x] 実写背景のベンチ（`tests/real_backgrounds.rs` と
        `tests/fixtures/backgrounds/`）。診断値が正解由来の誤差と相関することを
        27 点の順位相関で固定した（ρ=0.833 / 0.891。壊滅ケースである R シーンの
        既定値を除いた 20 点でも 0.759 / 0.844）。**ベンチが欠陥を見て
        いなければ、以降の改善は測れない**
  - [x] 2 つの測り方を直した。`rim_contamination` は平均色への近さを
        **散らばり（σ）で正規化してから**比べる形にした。前の形は `refine` が
        色から解いたアルファを同じ物差しで測り直すだけで、定義上ほとんど 0 に
        なっていた（R1 assisted で正解 0.512 に対し 0.028）。`contour_roughness`
        はチャンファーの 1px 刻みの中央値をやめて平均にした。中央値では値が
        0 か 1/scale かの 2 値にしかならず、しきい値が解像度の関数になっていた。
        実写リモコン（最良設定）は 0.019 → 0.096 / 0.175 → 0.391、
        `RIM_CONTAMINATION_WARN` の両側の余裕は 1.3 倍から 3.8 倍以上になった
  - [x] クリーン側の対照として R7（実写の照明とノイズを持つが欠陥は無い）を
        足した。**誤警報の較正が合成シーンだけに依っていると、しきい値が
        「実写であること」に反応していても気づけない**
  - [x] 手持ちの正解つき実写を差し込む入口（`KIRI_BENCH_DIR`）
  - [x] `halo_ratio` の「境界近傍か」をチェビシェフ距離変換へ置き換える。
        値は 1 ビットも変わらないまま、12MP で 120.7ms → 34.4ms（3.5 倍）。
        **ただし `diagnose()` 全体は速くなっていない。** 新しい 2 つが 108ms を
        足すので 129.5ms → 150.9ms（+21ms）である。速くなった部分だけを見て
        全体を語っていた
  - [x] 指標として何を主張できるかを直した（レビュー指摘の反映）
        - `rim_contamination` の 2 択を**線形 RGB**で行う。sRGB ではガンマぶん
          暗い側へ偏り、「色から読めるアルファが 1/3 未満」という `RIM_NEARER`
          の読み替えが成り立たない。黒商品の偽の信号が 6 分の 1 になり、較正の
          窓は 3 倍広くなった
        - 判定不能を黙って分母から外さない。窓に確定前景が無ければ近くから
          借り、それでも帯の半分を判定できなければ `null` を返す。R4 既定は
          真の背景 22.4% を掴みながら 0.000 を返していた（いまは 0.220）
        - `contour_roughness` はチャンファーの飽和値（85px）を平均に混ぜない。
          平滑化が届く 3r で頭打ちにする（S9 は 35.026 → 2.493）
        - 較正の母集団を正解だけで決める（`contour_error` と `rim_truth` の
          境目で分ける）。受け入れ基準が名指しするシーンをクリーン側に置くと、
          較正がテストを見てテストが較正を見ることになる
        - `RIM_CONTAMINATED` の hint は `HALO_REMAINS` が一緒に出ているときだけ
          付ける。汚染だけが出ている状態では tolerance を動かしても値が動かない
  - [x] トライマップ入力（`--trimap`）→ Phase 11
  - [x] matting と境界の平滑化 → Phase 12
  - [x] 照明場を持つ背景モデル → Phase 13 で実装した
- [x] Phase 11: 空間的な指示

        もう余地が無い**——最良設定の周りで 4 ノブを振っても指標は 1 桁目まで

        （根拠は design.md 4.9）
  - [x] 確定背景をフィルの種にする。**商品に囲まれて外周から届かない背景は、
        種にしない限りどんな色の規則でも消せない。** 測地的オープニングでも
        起点にして、細い指示を前景へ塗り戻さない
  - [x] 重なりは `CONSTRAINT_CONFLICT`、寸法違いは `MASK_SIZE_MISMATCH` で断る。

  - [x] `constraints` ブロック（効いた入口と 3 つの比率）と、`--preview` への
        重ね描き（確定前景が緑、確定背景が赤）。**座標は自分で書いたものなので
        数字では検算できない**
  - [x] `batch` の spec と `KIRI_BENCH_DIR` の `<name>.json` でも同じキーで受ける
  - [x] ベンチに R1 の `trimap` / `polygon` 設定を足した。輪郭誤差は
        assisted 18.42 に対して trimap 3.76 / polygon 19.76。**粗いトライマップ
        （不明の帯が長辺の 4%）でも、輪郭の位置を絞り込むだけで 5 分の 1 になる**
  - [x] 指示を渡さない経路の出力が 1 バイトも変わらないことを、旧バイナリとの
        突き合わせ（本出力・プレビュー・デバッグマスク・12MP の AVIF）と
        S/R 全 29 点の数値で確認した
  - [x] 不明の帯を matting の作業領域にする → Phase 12（**確定領域を帯から
        外す形で入れた**。不明領域をまるごと帯にすると、遷移そのものより広い帯が
        張られて確定 F/B が窓から消える——R1 trimap の輪郭誤差 1.39 → 3.86、
        rim 正解 0.128 → 0.256）
  - [x] 切り抜き済み PNG のアルファをそのまま指示として受ける入口
        （`--alpha-trimap` / spec の `alpha_trimap`）。アルファ 250 以上を確定
        前景、5 以下を確定背景、そのあいだ（半透明＝境界）を不明として読む。
        **`--trimap` と分けた**——同じファイルが 2 通りに読まれる形にすると、
        切り抜き済みの PNG を `--trimap` へ渡したときに黒い商品が「輝度 63 以下
        ＝確定背景」と読まれて指示が裏返る。255 / 0 ちょうどにしないのは、
        アルファが非可逆の容器を一度でも通っていると平坦な面が数段振れる
        ためで、±5 なら遷移の帯を 1px も広げずに吸える。アルファを持たない
        画像（JPEG）は全画素が確定前景になるので `CONSTRAINT_ALL_OPAQUE`
        （新設、exit 2）で断る。**一度切ったものを戻しても確定した画素が
        動かないこと**を CLI テストで固定した

- [x] Phase 12: 境界を matting として解く
  - [x] 局所色の格子と σ 正規化の 2 択を `cutout/local_colour.rs` へ切り出し、
        診断（`rim_contamination`）と処理（縁の再分類）が**同じ定義**を見るように
        した。2 箇所に持てば必ず離れ、離れた瞬間に「指標は良くなったのに絵は
        変わっていない」が起きる。較正表 29 点は 1 ビットも動かない
  - [x] (b) 縁の再分類。帯の中の二値画素を局所の F/B で塗り直す。**判定は
        3 値**（B 寄り / F 寄り / どちらとも言えない）に広げた——診断は
        「B 寄りか否か」しか問わないが、マスクを塗り直す側は「色が何も言って
        いない画素」を動かしてはいけない
  - [x] (c) 色の門つきメディアン。変化した画素のうち色が変化に矛盾するものを
        戻す。**フィルが背景と決めた画素を形の多数決で前景へ戻さない**——
        櫛の幅 3px の隙間（`--seal 1` が「塞がない」と約束した幅）がそれで塞がる
  - [x] (e) guided feathering（`cutout/guided.rs`）。ε を窓の中の確定背景の
        分散から決める。**色で決められなかった画素は対象から外す**——そこで
        回すと a ≈ 0 に落ちてただの箱ぼかしになり、S9 で「輪郭が滑らかに
        なったのに真の位置からは遠のく」が再現した
  - [x] 塗り直しを `changed == 0` まで繰り返す（上限 4）。1 パスで剥がせるのは
        帯幅ぶんだけだが、実写の不織布ではマスクが 20px 級はみ出す。**上限は
        出力の質で決める**——7 パス以上で長辺 1000px の 7x7 の突起が丸ごと落ち、
        5 パス以上で良品（R2 assisted、正解の輪郭誤差 0.96px）の粗さが
        `CONTOUR_ROUGH_WARN` まで 16% の距離に入る
  - [x] **累積の移動量に上限を置く**（`2 × max_radius`）。「帯の外を触らない」は
        1 パスの性質でしかなく、パスごとに帯を引き直すぶん累積では
        `RESHAPE_PASSES × max_radius` 動きうる。保証はパス単位ではなく累積で立つ
  - [x] `--seal` が塞いだ隙間を**帯から外す**。戻すだけでは射影アルファが同じ色を
        見て 0 で塗り潰し、README の約束が境界処理の中で取り消されていた
  - [x] 塗り直しが開けた穴と `--seal` が塞いだ隙間を、測地的オープニングで
        前景へ戻す。戻すのは元の二値マスクで前景だった画素だけ（商品に囲まれた
        確定背景を埋めない）
  - [x] `--matting` / `--smooth-contour` / `--no-reclassify` と `settings` の
        5 項目。`band_min_radius` と `smooth_radius_px` は**実際に効いた**値で、
        指定値からは読めない（`--smooth-contour` は長辺 1000px 換算、上限 16）
  - [x] `refine` が `Constraints` と `bbox` を受け取る。確定した画素は帯から
        外れ、輪郭の粗さは診断と同じ規約（矩形の辺を数えない）で測る。ベンチに
        `forced_bg_kept` を足し、R1 の trimap / polygon で 1.0 を固定した
  - [x] `--matting projection --smooth-contour 0 --no-reclassify` が Phase 2 と
        1 バイトも変わらないことを、旧バイナリとの md5 比較（S/R 全 20 シーン、
        assisted 5 通り、20MP の実写）で確認した
  - [x] 帯幅の**下限**を長辺 1000px 換算で読む（`--cleanup` と同じ規約）。
        上限は原寸 px のまま——掛け戻すと遷移より広い帯が張られ、10 / 14 / 20 /

  - [x] (b)(c) の確保を削る。`smooth_in_band` の積分画像を 128px タイルへ切り、

        積まないようにした。24.5MP の実写でピーク RSS の増分が +546MB → +32MB
  - ※ **`rim_contamination` の 0.061 は帯の広さの問題ではない。** 実写リモコンが
        目標（0.05）に届かないのを「境界処理の届く帯が高解像度で足りない」と
        読んでいたが、3 方向から潰れた。深さ別の内訳では残る汚染の 77% が
        深さ 0〜2px、つまり帯（24.5MP で下限 10px）のまっただ中にある
        （design.md 4.10）。帯幅の上限を解像度で掛け戻すと 0.061 → 0.133 と
        悪くなる（同 4.8）。そして `--border` / `--feather` を px@1000 に
        しても 0.0611 → 0.0609 しか動かず、`halo_ratio` は 0.0296 → 0.0313 と
        悪くなる（同 4.11）。**次の一手は帯ではなく (d) の射影**——帯の外の
        確定 F/B の平均ではなく、帯の中の色の言い分に素直に従う射影である
  - [x] 合成 S3（淡色商品、輪郭 ΔE 9.5）の `HALO_REMAINS` の偽陽性を潰した。
        **原因は matting ではなく指標の循環だった。** `halo_ratio` の局所背景は
        窓の中の透明画素の平均だが、輪郭の色差（S3 で ΔE 9.5）が `--tolerance`
        （12）を下回る素材では**フィルが商品の外縁を食う**。食われた画素は
        透明なので参照の材料になり、参照色が商品色そのものへ寄る（halo と
        数えた 509 画素の平均は画素 218.1 / 参照 218.5、大域の背景は 248）。
        hint の「`--tolerance` を上げろ」は「商品をもっと食え」の意味になって
        いた。**参照の材料を背景モデルと矛盾しない透明画素だけに絞る**
        （許容 ΔE = 外周の残差 p90 の 2 倍、下限 3）。S3 は 0.1054 → 0.0000、
        本物の欠陥 S9 は 0.5356 → 0.2366 で警告は残り、実写の `--tolerance` の
        導線は tol 12 が 0.163 → 0.2275 と**太くなった**（12/20/30/46 が
        0.2275/0.1396/0.0718/0.0235 と単調減少）。較正表 29 点と `--optimize` の
        R1〜R7 は 1 ビットも動かない。`the_matting_stages_never_add_a_warning`
        の免除は消した（design.md 4.10）。門の倍率（残差 p90 の 2 倍）は
        **飽和の入口**である——狭めると指標が本物の背景まで参照から落とし、
        `halo_ratio` を過小に言い始める。参照の判定は画素ごとに 1 度だけ掛ける
        （窓の中で掛け直すと `--optimize` が 12.9 → 16.1 秒まで伸びた）
  - [x] 帯だけを切り出した closed-form matting（髪の毛・半透明の袋）。
        **入れたが、的は下に書いたところには無かった。** R6 の `alpha_mae` は
        0.1195 → 0.1733 で悪化する（**原因は帯幅ではない**。§9.9 で覆した）。当たったのは
        織り目のある実写背景で、受け入れ条件は §8.6 で差し替えた。結果は §8.10。

        0.1321 / 0.1195 である（S9 の 0.33 と R3 の 0.46 は切り抜きそのものが
        壊れている点なので的ではない）。**受け入れ条件は「R6 の alpha_mae が
        0.1195 を下回り、他の 20 点が現状比 +0.005 以内」**になる。
        なお `guided` は R6 を 0.1321 → 0.1195 と改善する一方で R1 / R2 / R5 を
        0.077 → 0.090 / 0.059 → 0.068 / 0.080 → 0.094 と悪化させており、
        「均せば良くなる」素材と「均すと崩れる」素材が分かれている。
        **費用は既定の経路へは載せられない。** 行列自由の共役勾配でも
        24.5MP の帯（約 200 万画素）で 1 反復 0.1〜0.2 秒、200 反復で
        20〜40 秒になる。`--matting closed-form` の 3 つ目の値として
        持つ形になる（既定は `guided` のまま）。
        **着手の計画は [8. Phase 27](./08-phase-27.md) にある。**
        **帯幅が的だというその診断を検証して直す段は
        [9. Phase 28](./09-phase-28.md) にある。**
