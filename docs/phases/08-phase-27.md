# 8. Phase 27: 帯だけの closed-form matting

節番号は分割前のまま変えていない。`計画 §8.6` のような参照が他の節・src / tests から
150 箇所以上張られていて、**番号が識別子として働いている**からである。どの節がどの
ファイルにあるかは [実装計画](../implementation-plan.md) の索引で引く。

§7 が「EC の運用へ寄せるために足すもの」を Phase 26 で使い切ったので、ここからは
**入口の品質へ戻る**。§5 に残る `[ ]` は 1 件だけで、README も冒頭でそれを名指し
している（「残るは帯だけの closed-form matting」）。**選ぶ余地がほとんど無い**のが
この段の位置づけである。

## 8.1 なぜここか

1. **残件がこれしかない。** §5 の `[ ]` は Phase 12 の 1 件で、§7 のロードマップは
   Phase 26 で閉じた
2. **Phase 17〜26 は出力側だった。** 契約・規格・既定値は配り終えたので、次に
   残るのは切り抜きそのものの精度である
3. **的は既に測ってある。** §5 Phase 12 の `[ ]` に着手前の実測が書いてある——
   境界アルファの誤差（正解の輪郭 ±3px での平均絶対誤差）は S1〜S13 と R1〜R7 の
   ほぼ全点で 0.005〜0.046 しかなく（`projection` の列。§8.8 で確かめた）、
   残っているのは**柔らかい輪郭だけ**である。
   S4（8px、sRGB 合成）が `projection` 0.1387 / `guided` 0.1389、R6（8px、線形
   合成）が 0.1321 / 0.1195
4. **受け入れ条件も既に決まっている。** 「R6 の `alpha_mae` が 0.1195 を下回り、
   他の 20 点が現状比 +0.005 以内」。§6 が P2 へ課した「着手前にベンチで見積もる」
   は、**この 1 件については済んでいる**

## 8.2 作るもの

`Matting`（`cutout/refine.rs`）に 3 つ目の値 `ClosedForm` を足す。**既定は `Guided`
のまま**で、既定経路のバイト列は 1 ビットも動かさない。

解くのは帯（`in_band`）だけである。帯の外は確定なので境界条件になり、
**トライマップ／マスク／多角形で確定させた画素は仕様上そもそも帯に入らない**
（`RefineOptions::constraints`）ので、確定領域はそのまま境界条件として効く。
**新しい規約を 1 つも足さずに済む**のが、この形を選ぶ理由である。

## 8.3 費用と、費用への備え

行列を作らない共役勾配でも、24.5MP の帯（約 200 万画素）で 1 反復 0.1〜0.2 秒、
200 反復で 20〜40 秒になる（§5 Phase 12 の見積もり）。**既定には載せられない。**
載せない代わりに、次の 3 つを同時に置く。

- **反復上限と残差での停止。** 収束していないことを黙って返さない
- **打ち切りを名乗る warning code を 1 本。** `warning.rs` のカタログへ足す以外に
  作る方法が無い構造（§7.4）は、ここでも同じに効く。**名前はここでは決めない**——
  `tests/cli.rs` には「計画書が名指しした未実装の code」を先に通しておく表があり、
  そこへ載せた名前は実装で変えにくくなる。停止条件を決めてから名乗る。
  **この段落が名前を書かないこと自体が、その検査の要求でもある**——計画書が
  名指しした大文字の語は、実在する code か定数でなければ `cargo test` が落ちる
- **`--optimize` の探索段には載せない。** 探索段は 1500px・refine 無しで、そこへ
  40 秒の経路を置くと 1 回の探索が分単位になる（Phase 15 の探索は 13.9 秒）

メモリは**帯の外接矩形ではなく帯の画素だけ**を持つ。Phase 3 のレビューで
`close_new_gaps` の BFS シードとメディアンの積分画像が 24.5MP でピーク RSS
+546MB を出した前例が、そのまま当てはまる。

## 8.4 契約への影響

`schema_version` は **2 のままである。** README の規約は「キーが増えただけでは
上げない。既存のキーの意味や型が変わったときだけ」で、**値の追加は既存の読み方を
誤読にしない**。

| 場所 | 変更 |
|---|---|
| `--matting` の `value_enum` | 値が 1 つ増える。**長いヘルプ（`cli.rs`）も 3 つ目を説明する**——いまの文面は 2 値しか語っていない |
| `kiri schema` | `options[].accepts` は `get_possible_values()` から組む（`commands/schema.rs`）ので、**書かなくても増える** |
| `batch` の spec | **手を入れる場所が無い。** 綴り検査は `value_enum::<Matting>()` が `clap::ValueEnum` から候補を引く（`commands/batch.rs`）ので、枝を足せばそのまま通る |
| `settings.matting` の書き出し | `commands/cutout.rs` の `match` に枝が要る。**コンパイラが止める**ので落ちない |
| 値を書き写した doc コメント | `batch.rs` と `report.rs` の「（"projection" / "guided"）」は**手書き**なので 2 箇所とも直す |
| `warning.rs` | 打ち切りを名乗る code を 1 本 |
| README | `--matting` の表、「境界は matting として解く」の節、**冒頭の「残るは」の 1 文を消す** |

## 8.5 テスト方針

1. **着手の第一歩は測り直しである（済。§8.8）。** §5 Phase 12 の 21 点の数値は
   Phase 12 時点のもので、その後 Phase 13（照明場）以降が入っている。**現状の
   `alpha_mae` を 21 点ぶん先に表にした。** S4 と R6 は 4 桁で一致し、的は動いて
   いなかったので、受け入れ条件は据え置く
2. R6 / S4 の改善を固定する（先に落ちるテストを書く）
3. 他 20 点の非悪化（現状比 +0.005 以内）
4. **既定経路の非破壊。** `guided` の出力が 1 ビットも動かないことを md5 で見る
5. **決定性。** 共役勾配は加算順序で結果が動く。和の順序を固定し、2 回実行の
   バイト一致を見る
6. 打ち切りが効き、警告が出ることを固定する
7. clippy / fmt / MSRV / `--features segment` の有無で 2 系統。**feature 違いの
   `cargo test` は直列で回す**——同時に走らせると `target/release/kiri` を
   取り違えて偽の失敗になる

## 8.6 受け入れ条件（**差し替えた**）と中止条件

### 着手前に立てた条件

**R6 の `alpha_mae` が 0.1195 を下回り、他の 20 点が現状比 +0.005 以内。** 満たせ
なければ実装ごと落とす、と決めていた。

### 外れた事実

**R6 は 0.1195 → 0.1733 で悪化した**（§8.10）。原因は解き方ではなく帯幅である——
帯の半径は S4 で 2px / R6 で 3px しかないのに、真の遷移は 8px にわたる。帯の外は
0/1 に固定されるので、帯の中で遷移を完結させるしかなく、必ず真の傾斜より急になる。
窓を 3×3 から 9×9 まで広げても 0.1452 で頭打ちになり、しかも織り目の側を悪化させる。

**※ これは誤りである。下限を帯幅と読み違えている。実測は §9.9。** 半径 2px / 3px は `settings.band_min_radius`
（帯幅の**下限**）で、画素ごとの半径は S4 で p50 6px、R6 で p50 8px ある。悪化した
事実（0.1195 → 0.1733）は動かないが、**その原因の説明が誤っていた。**

**この条件はこの段では満たせない。** 満たすには帯幅を変えることになり、それは
`refine` の (b)(c) と較正表 29 点へ波及する別の工事である。

### 差し替えた条件

**条件を消さずに差し替える。** 測って分かったのは「的が別の場所にあった」ことで、
「何も効かなかった」ことではない。新しい条件は**測る場所を移し、強さは緩めない**。

1. **織り目のある実写背景で `guided` より良い。** R1 で輪郭誤差と帯の正解側の汚染が
   **半分以下**、`alpha_mae` も下がる（`closed_form_halves_the_truth_side_error_on_a_woven_background`）
2. **品質ゲートを合否でまたぐ。** 同じ R1 で `contour_roughness` と
   `rim_contamination` が、`guided` では警告側・closed-form では合格側にある（同テスト）
3. **既定経路が 1 ビットも動かない。** 既定は `guided` のままで、既存の出力は
   変わらない。**裏は §8.10 の表の `guided` 列が §8.8 と 4 桁で一致すること**で
   取れている（S1 0.0074 / S4 0.1389 / R1 0.0901 / R6 0.1195）。`smooths_alpha()`
   への書き換えは `== Matting::Guided` と同じ枝を選んでいる
4. **負ける素材が名指しされている。** 柔らかい輪郭と 3px のストラップで負ける事実が
   README とテストの両方にある（`closed_form_loses_on_soft_edges_and_thin_straps`）
5. **解き切れなかったことを黙らない。** 上限で止まったら `MATTING_NOT_CONVERGED`
   （`only_an_unfinished_matting_warns`）
6. **同じ入力で 2 度解いてバイト一致**（`closed_form_is_deterministic`）

**4 番を条件に入れているのが要点である。** 「効く」だけを条件にすると、次に読む人が
既定を差し替えたくなる。**負けることの証拠を機械が持っている**状態までを合格とする。

### いまの中止条件

上の 6 つのどれかが落ちたら落とす。**とくに 3 番が落ちたら、他が全部通っていても
落とす**——素材で勝ち負けが分かれる機能が既定の出力を動かすのは、勝ち負けの話より
先に契約の話になる。

- ※ **条件を差し替えたこと自体を残す理由。** 「条件を満たせなかったが残した」だけを
  書くと、次にこのコードを読む人は「通っていない機能」として扱うか、逆に「条件など
  飾りだ」と読む。どちらも間違いである。**測って的が動いたなら条件も動かす、ただし
  緩めない**、というのがここでやったことである
- ※ **`guided` が R6 を改善しながら R1 / R2 / R5 を悪化させた分岐**（0.077 → 0.090 /
  0.059 → 0.068 / 0.080 → 0.094）は、着手前に「同じ分岐が起きうる」と書いていた。
  **起きた。しかも向きが逆だった**——closed-form は R1 / R2 / R5 を改善して R6 を
  悪化させる。2 つの解き方は同じ線の両側にいる

## 8.7 却下した代替案

- ※ **既定を `closed-form` にする。** 20〜40 秒を全実行へ載せる理由が無い。効くのは
  21 点中 2 点で、残り 19 点の誤差は既に 0.005〜0.046 である
- ※ **帯ではなく全画素で解く。** 24.5MP 全体は 1 桁以上高く、確定領域を解き直す
  意味が無い。帯は Phase 12 で既に「色で決め直してよい場所」として定義してある
- ※ **`guided` を置き換える。** 素材で優劣が分かれている以上、**選べる形で持つ**のが
  正しい。`projection` を残したのと同じ判断である
- ※ **Phase 26 が名指しした「`set` があるときセット全体で段を 1 つ決める」を
  ここへ混ぜる。** あれは `batch` の設計変更で、境界品質とは別系統である。Phase 26 が
  「既定値の根拠を引き直す段に `batch` の設計変更を混ぜない」と書いたのと同じ理由で、
  **境界を解き直す段にも混ぜない**

## 8.9 ソルバの設計

**実装したら design.md へ移す。** 本書は進め方だけを扱う（§冒頭）ので、ここに置くのは
着手前に決めておかないと手が止まる判断だけである。

### 8.9.1 差し込む場所は (e) の置き換えである

`refine()` は帯を作ってから 3 段を回す——(b) 再分類 / (c) 色の門つき平滑化 /
(e) guided feathering——そして (f) で最終アルファから色を復元する
（`cutout/refine.rs`）。**closed-form は (e) の位置にそのまま入る。**

```
guided:      射影アルファ → guided::feather(…) → (f) 色の復元
closed-form: 射影アルファ → closed_form::solve(…) → (f) 色の復元
```

`guided::feather` と同じ引数（元画像・`lut`・二値マスク・帯・射影アルファ・
`Solved`・帯幅）で足りる。**(f) より前に最終アルファが確定していることだけが
契約で**、そこは guided と同じである。

- ※ **`despill` の遅延は guided だけの条件になっている。** いまの
  `despill: opts.despill && !guided_matting` は「均す段があるなら色の復元を
  最後まで待つ」という意味なので、**closed-form でも待たなければ縁が色づく。**
  `guided_matting` を「アルファを均す段があるか」へ読み替える。`Solved` の確保も
  同じ条件にぶら下がっている（いまは guided のときだけ 12MP で 1.5MB を確保する）

### 8.9.2 未知は「帯 かつ 色から決まった」画素だけである

未知にするのは**帯の中で `Solved` が真の画素**に限る。帯の中で色から決まらなかった
画素は、射影アルファの値のまま**既知側へ回す**。

**これは guided が既に払った授業料である。** 色が matte について何も言わない場所
（淡色商品 × 白背景、マスクが商品の内部で止まった場所）で均すと、guided filter は
a ≈ 0 に落ちてただの箱ぼかしになり、**合成 S9 で輪郭誤差 19.9 → 27.8、粗さ
2.49 → 0.02**、つまり壊れた切り抜きが指標の上でだけ良く見える状態になった
（`cutout/guided.rs` の `Solved`）。closed-form でも同じことが起きる——F と B が
見分けられない窓では matting Laplacian がほぼ退化し、解は境界条件だけで決まる、
すなわち**幾何的な内挿**になる。§8.8 が示した S9 0.3345 / R3 0.4651 はまさにその
2 点で、**そこは的ではない**。

解く系は帯の内側だけの Dirichlet 問題である。

```
L_bb x = −L_bk α_k      x = 未知（帯 ∩ Solved）、α_k = 既知（帯の外 + 未解の帯画素）
```

右辺は**既知側のアルファへ同じ演算子を 1 度掛けて**作る。専用の式を書かない
（2 通りの実装は必ず離れる）。

### 8.9.3 窓係数は guided の材料からそのまま作れる

Levin の窓ごとの係数は `(Σ_k + ε I)^{-1}` である。**guided が既にそれを作っている。**
`guided::solve()` は積分画像（`Integral<10>`）から窓の平均 μ と共分散の上三角
`m00..m22`（ε を対角へ加えたもの）を組み、余因子で 3×3 の逆を解いている。
closed-form が要るのは `a = Σ̂^{-1} cov` の **一歩手前の `Σ̂^{-1}` そのもの**だけで、
材料は 1 つも増えない。

行列は作らない。窓 k（画素数 n、端では切り詰まる）の寄与を、ベクトル α へ次の
2 段で掛ける。

```
s = Σ_j α_j                     v = Σ_j α_j (I_j − μ_k)
out_i += α_i − (1/n)( s + (I_i − μ_k)ᵀ Σ̂_k^{-1} v )
```

1 窓あたり 100 flop 前後で、帯 200 万画素なら 1 反復 200 Mflop。**§8.3 の
「1 反復 0.1〜0.2 秒」はこの見積もりと合う。**

### 8.9.4 Σ は 3×3、ε は帯幅の窓で測る

**2 つの窓を分ける。** Σ は Levin と同じ 3×3 で採り、ε は `guided::epsilon()` を
そのまま呼んで**帯幅の窓**（`min_radius + GUIDED_MARGIN`）で測る。

理由は 2 つある。**Σ を広げると局所の色モデルが鈍る**——それは guided が既に
やっていることで、closed-form を足す意味が無くなる。逆に **ε を 3×3 で測ると
確定背景が窓に 1 画素も入らない**場合がほとんどで、`epsilon()` は `EPS_FLOOR` へ
落ちる。ε は素材の雑音の床（σ0 = 0.015、JPEG q90 の平坦部のばらつき）であって
3×3 の性質ではないので、**帯の尺度で測るほうが読みと合う**。

色は線形 RGB で扱う（`lut` 経由）。ε が線形 RGB の分散として定義されているので、
ここを sRGB で解くと床の意味が変わる。

### 8.9.5 Jacobi 前処理つき共役勾配、初期値は射影アルファ

- **初期値は射影アルファ。** 0 から始める必要がない。§8.8 の表のとおり `projection`
  は 19 点で 0.0053〜0.0457 に入っており、**的の 2 点でも 0.1387 / 0.1321** である。
  §8.3 の「200 反復」は 0 から始めた場合の見積もりで、**実測はもっと少ないはず**
  という予想をここに書いておく（外れたらそれも記録する）
- **前処理は Jacobi。** `diag(L)` は窓の寄与を 1 パス足すだけで作れて、帯画素 1 つに
  f32 1 個で済む。Levin 自身は疎行列の直接解法なので前処理の前例が無く、**行列を
  作らない以上、対角より重い前処理は係数の持ち方そのものを変える**
- **クランプは最後に 1 度だけ。** 反復の中で [0,1] へ丸めると共役性が壊れて収束
  しなくなる。解き終えてからクランプし、u8 へ量子化する

### 8.9.6 停止条件は u8 に結びつける

**残差の絶対値には意味の基準が無い。** 出力は u8 のマスクなので、量子化の半分
（1/510）より小さい変化は**書き出したバイトに現れない**。

```
反復を止める: max|Δα| < 1/510   または   反復が上限に達した   または   残差が減らない
```

3 つ目は保険である。matting Laplacian は半正定値だが、端で切り詰まった窓と f32 の
丸めで CG が停滞しうる。**10 反復のあいだ残差の最小値が更新されなければ打ち切る。**

- ※ **相対残差のしきい値（1e-4 など）は置かない。** 選ぶ根拠が無く、素材によって
  意味が変わる。「u8 で見えない改善のために反復しない」は、**素材に依らず同じ
  ことを言う**唯一の基準である

### 8.9.7 決定性は「並列にしない」で買う

`refine` と `guided` の走査は**どちらも逐次**である（`for_each_tile` も
`guided::feather` も `while` の二重ループで、rayon を使っていない）。closed-form も
同じにする。窓はラスタ順に 1 度ずつ、内積は帯の添字順に f64 で畳む。

**並列化は後から足せるが、決定性は後から足せない。** `--jobs` は `batch` の項目
ごとの並列で、1 枚の中を割る仕組みは refine にもともと無い。

### 8.9.8 メモリは opt-in のぶんだけ増える

帯 200 万画素での見積もり。

| もの | 大きさ |
|---|---|
| 窓係数（`Σ̂^{-1}` の上三角 6 + μ 3 = f32 9 個 = 36B） | 72MB |
| Jacobi の対角（f32 1 個） | 8MB |
| CG のベクトル 5 本（x / r / p / z / Ap、f32） | 40MB |
| 合計 | **約 120MB** |

既定経路の 24.5MP は Phase 15 の実測で 892MB なので、**opt-in の段で +120MB** になる。
**帯の外接矩形ではなく帯の画素だけを持つ**ので、Phase 3 が踏んだ +546MB
（BFS シードが背景全画素、メディアンの積分画像が帯の外接矩形）の形にはならない。

- ※ **窓係数を f16 に落とす手は残してある。** 36B → 18B で 72MB が 36MB になる。
  推論を f16 へ畳んだ前例（Phase 14）はあるが、あちらは前向き計算で、こちらは
  **CG の条件数に直接効く**。まず f32 で測り、RSS が問題になってから考える
- ※ **係数を反復ごとに作り直す手は採らない。** メモリは O(タイル) で済むが、
  積分画像を 200 回張り直すことになり、1 反復の費用が倍以上になる

### 8.9.9 打ち切ったら言う。guided へは落とさない

反復上限に達して `max|Δα|` が基準を超えたままなら、**警告を 1 本出す**（名前は
§8.3 のとおりまだ決めない）。

**帯が大きいときに guided へ落とす案は採らない。** 利用者は既定でない値を明示して
20〜40 秒を承知で呼んでいる。そこで黙って別のアルゴリズムに替えると、
`settings.matting` が `closed-form` を名乗ったまま中身が guided になる——
**契約を自分で配る設計で、いちばんやってはいけない嘘**である。遅いことは
時間で分かるが、すり替えは JSON からは分からない。

### 8.9.11 却下した代替案

- ※ **帯を粗くしてから解いて拡大する。** 帯幅は長辺 1000px 換算で 3〜10px しか
  なく、粗くすると解くべき構造そのものが消える。加えて、**帯域制限を伴わない縮小は
  勾配を相対的に強める**ので、「粗くすれば軽くなって滑らかにもなる」は成り立たない
- ※ **未知を帯の全画素にする。** §8.9.2 のとおり S9 / R3 で幾何的な内挿に落ちる。
  `Solved` の印は既にあるので、使わない理由が無い
- ※ **Σ の窓を帯幅にそろえる。** guided と同じものになる
- ※ **直接解法（疎 Cholesky）。** 200 万元の疎行列を分解する crate を pure Rust で
  持ち込むことになり、`Cargo.toml` が `tract-onnx` について立てた基準
  （`*-sys` が 1 つも現れない）を満たすものを探す話が先に立つ。CG なら依存ゼロで
  書ける
