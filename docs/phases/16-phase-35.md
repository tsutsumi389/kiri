### 読み取り

1. **`refine` 冒頭の `image.clone()` は 2ms しかかからない。** 98MB の写しは
   ページを触るまで実体が無いので、費用は後段に散る。最初の 140ms の正体は
   `contour_roughness`（平滑化 77 + チャンファー 47 + 輪郭の抽出 15）だった
2. **`sweep_bands`（Project）の 95ms のうち 67ms は受け皿の幾何的フェザーだった。**
   色で決められなかった画素が 1 つでも出ると、`OnceLock` の中で全面の
   `feather::feather` を 1 本のスレッドで作り、その間、同じ受け皿を待つ他の
   帯が止まる
3. **`close_new_gaps` の 57ms は BFS ではない。** BFS は 3ms で、残りは帯の
   外接矩形（ほぼ商品全体、530 万画素）を 1 画素ずつ舐める走査が 5 本あった
4. フィルも同じ形をしていた。`fill_from_border`（1 回 80〜90ms、フィル 1 回に
   2 回）、`push_frontier`（35ms × 4）、`seal_narrow_gaps` の全画素走査 2 本
   （計 80ms）。BFS そのものより、全画素を 1 本で舐める段のほうが重い

## 16.3 並列化の型

使った型は 4 つしかない。どれも §11.5 の 3（「出力の添字ごとに書くか、整数の
和だけを取る」）の中に収まる。

1. **行（またはタイルの行）で割る。** 書き先が自分の行だけで、読むのが入力
   だけの段。`band_map_into` の塗り、`reclassify_rim`、`smooth_in_band`、
   `guided::feather`、`local_colour::build`、`halo_of` の数え上げ。和はどれも
   整数か、タイルの中で 1 本のときと同じ順序で足す浮動小数である
2. **行に揃えた語の面。** `BitPlane` は画素の添字をそのまま詰めるので、語が
   行をまたぎ、行で割ると書き先がぶつかる。帯の中だけ「1 行 = `w.div_ceil(64)`
   語」の面を持ち、出入口で `read_bits` / `insert_bits` で詰め直す
   （`separable_rows`、`close_new_gaps`、`expand_closure`、`edge_ridges`）
3. **連結成分で答える。** 埋まる集合が「ある性質の画素の連結成分のうち、
   起点を含むもの」と言い直せる段は、行のランを並列に切り出して union-find で
   結ぶ（`fill_from_border` は 4 近傍、`remove_specks` は 8 近傍、
   `morphology::run_components` が共通）。辿る順序に依らないことが前提で、
   1 画素ずつ辿る素直な実装と一致することを試験で見ている
4. **上限のある距離は帯に割れる。** チャンファー距離を「`cap` を越えたか」
   「`cap` で頭打ち」でしか読まないなら、距離 `cap` の経路は上下 `cap / 3` 行
   しか動かない。帯をその分だけ上下に広げて測れば、`cap` 以下の値は 1 本で
   測ったものと一致する（`chamfer_capped`）。「窓に種があるか」しか問わない
   チェビシェフ距離は、そもそも正方形の膨張である（`near_to`）

**到達閉包も帯に割れる。** フィルの第 2 段の判定は Phase 30 §11.5 のとおり
フィルの状態を見ないので、答えは静的な有向グラフの到達閉包である。帯ごとに
自分の行を辿り、帯の外への一歩は判定してから隣の帯へ受け渡し、受け渡しが
尽きるまで回す（`expand_closure`）。帯の割り方（スレッド数）にも依らない
——rayon のスレッド数を決める環境変数で 1 本と 3 本にしても、10 通りの出力は
基準と一致した。
**距離を数える影の段（第 3 段）は 1 本のキューのまま**にした。帯に割ると
最短距離が 1 回では決まらず、ラベル修正の反復が要る。

## 16.5 ピーク RSS は動かさなかった

§11.11 の「増えた分を取り戻す道筋」には手を付けていない。段の印ごとに
`getrusage` の最大値を一時的に出すと、山はこう積まれている（B8 時点）。

|---|---|
| 背景の推定 | 380 MB（読み込みの一時確保がここで決まる） |
| フィルの下ごしらえ | 530 MB（Lab の表 147MB） |
| フィル 2 回目 | 647 MB |

- 境界の帯で +157MB。出力用の `image.clone()`（98MB）と、帯ごとの作業域
  （14 スレッドでは 4 スレッドに絞ったときより約 56MB 多い。4 スレッドで 794MB）が主である。
  §11.11 の 1（書き換えた画素だけの重ね合わせ）が依然として最大の手である
- 終了直前の +40MB は `cutout_seen` の外（書き出し）で、この段の範囲の外である

  ランは数 MB 単位で、ピークの段（境界の帯）とは重ならない**ので、山は
  動いていない

## 16.6 受け入れ条件

1. 10 通りの設定（`check.sh`）の PNG の md5 が基準と完全一致する。2 回走らせて
   同じであること（決定性）
2. `cargo test --release`（feature の有無で 2 系統）、`cargo clippy --release
   --all-targets -- -D warnings`、`cargo fmt --check` が通る
3. **結果 JSON（`elapsed` を含むキーを除く）が基準と一致する。** PNG の md5
   だけでは診断（`halo_ratio` など）が動いても気づけない。バッチ 6 で
   `halo_of` に手を入れる前にこれを足し、それまでのバッチのバイナリも
   遡って一致を確かめた
4. 並列化で新しいプールを建てない（§11.5 の 2）。単枚の中の `par_iter` は
   大域プールか、`batch --jobs` が建てたプールに従う

## 16.7 踏んだ罠

1. **`OnceLock` の初期化の中で rayon を使うと止まる。** 受け皿の全面フェザーを
   並列にしたら、2 回に 1 回ほど固まった。初期化中のスレッドが `par_chunks`
   の完了を待つ間に作業盗みで別の帯の仕事を拾い、その帯が同じ `OnceLock` の
   `get_or_init` に入って**自分自身を待つ**。並列にするのはやめ、受け皿を
   帯ごとにタイルの分だけ作る形へ変えた（`Fallback`）。待ち合わせそのものが
   無くなったので、全面の 24.5MB も要らなくなった
2. **PNG の md5 は診断を見ていない。** 診断の値は結果 JSON にしか出ない。
   §16.6 の 3 を足すまで、`halo_of` を壊しても `check.sh` は通るところだった
3. **帯に割った到達閉包は、大きな領域が帯をまたぐと 1 帯ずつ進む。** フィル
   2 回目の第 2 段は受け渡しが 18 回に及び、各回は数件の受け渡しに対して
   1 つの帯が 4〜6ms かけて大きな領域を辿っている。1 本のキュー（124ms）より
   は速い（69ms）が、帯の数ほどには縮まない
4. **機械は温まる。** 同じ基準のバイナリが、作業の最初は合計 2733.7ms、
   数十分後は 2824.9ms だった。比べるのは同じ時間帯に測ったものどうしにする
5. **文書に環境変数名を書くと、code の検査が実在しない code として落とす。**
   §11.16 の「配る文面の縛り」と同じ罠を 3 度目に踏んだ（rayon のスレッド数の
   変数名）。名前ではなく何をする変数かで書く
6. **一時的な計測の印は `cargo fmt` が複数行に割る。** 1 行で書いた印を
   行単位で消す前提でいたら、整形後に閉包の断片が残ってビルドが落ちた。
   印は整形の後でも 1 塊で消せる形にしておく

### 試して捨てたもの

- **受け皿（幾何的フェザー）の全面を並列に作る。** 上の罠 1 で固まる。
  タイルごとに作る形へ置き換えた
- **`fast_image_resize` の縮小（主体の推定、35ms）を並列にする。** 外部の
  クレートの feature を足すことになり、バイト一致を保証できる根拠が kiri の
  中に無い。縮小を背景の見立てと同時に回す（`rayon::join`）ことで、待ち時間
  だけを消した

次にやるなら次の順になる。

1. **ピーク RSS。** 時間は 3.0 → 0.88 秒まで縮んだが、RSS は 856 → 849MB の
   ままである。§11.11 の 1（出力の写しを帯の画素の重ね合わせにする）が最大の
   手で、`cutout_seen` の出口と `apply_alpha` まで含めた工事になる
2. **影の段の帯分割。** 距離の上限つきの到達は、帯ごとにラベル修正
   （短い距離が届いたら辿り直す）で回せば最短距離に収束する。1 回 20ms × 2
3. **場の作り直し（約 35ms）。** `estimate_field` のセル走査はすでに並列で、
   残りは `fill_unknown` と外周の残差。小さい
